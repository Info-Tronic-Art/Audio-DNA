@@ITEM 236
TITLE: Snapshot: a save of the show exactly where it is
STATUS: ANSWERED he re-defines Snapshot against the item and against Harmony's answer
HIS: BF243 "a save of the show exactly where it is"; "push a shortcut button and save that to look out later"; BF257 "We keep the safe snapshot somewhere."
RULE: (1) WHAT IT IS. Snapshot is one command with a shortcut key of its own. One press saves the open show exactly as it stands at that instant, as a new snapshot. It asks nothing and opens no window. It works whether the show has a file or not and whether it has unsaved changes or not. (2) WHAT A SNAPSHOT HOLDS. (a) Everything a Save of the show holds (@@ITEM R188 (a) to (c) as amended): decks, clips, layers, effects with every slider as he has set it, actions and which are switched on, signals, envelopes, macros, the presets, the keyboard and MIDI mapping, the layout, the canvas size, which outputs were on -- taken from the show as it is at the press, unsaved changes included. (b) What a show does not keep: on every layer, which clip is playing and the frame it is on; the tempo number, where the beat stands in the bar, and whether the beat is running, paused or stopped; which actions are running and how far each has run. (c) A still picture of the output at that instant, at the size of the show's canvas, kept with the snapshot. (d) Not the sound: a snapshot holds no audio. (3) WHERE IT IS KEPT. Each snapshot is a file of its own in a snapshots folder of the app, apart from the shows. It is named by itself: the show's name with the date and time of the press. Taking a snapshot never writes to his show file, never makes the show count as saved, and never changes which show is the very last show. Media are not copied: a snapshot points at the same files the show does. Snapshots are kept until he deletes them; there is no limit on their number. Collect Media does not take them along. (4) LOOKING AT ONE LATER. The app lists the snapshots, each with its picture, the show's name, the date and the time, newest first; they are not listed among the shows. Picking one opens it in place of the show that is open, after the same question every opening of another show asks (@@ITEM R189 (d)). Unlike a show (@@ITEM 196), a snapshot comes up as it was: the clips that were playing are on their layers, each on the frame it was on, the actions that were running are on, and the tempo is paused at the place in the bar where it stood; the tempo's play runs everything on from there. What the outputs do when it opens is the same as for any show (topic G's rule). It opens as a show that has no file of its own: Save asks for a name, as for a new show, so the snapshot file is never changed and the show it was taken from is never written over by it. The app never opens a snapshot by itself. (5) IT NEVER DISTURBS THE SHOW. Taking a snapshot never makes the picture, an output or a control stutter, never pauses anything and never takes the keyboard away; the state is copied in one frame and the file is written, read back and checked away from the picture, as a Save is. A snapshot that worked shows nothing; one that failed shows the "Save failed" box. (6) The separate command that only saves a still picture of the output is gone: the picture comes with every snapshot. (7) The shortcut key is part of the keyboard and MIDI mapping and can be put on a pad like any button (topic J's rule).
CHANGED: The item kept Snapshot as "one small command that saves a still picture of the output to a file"; Harmony's answer said the same. His words replace both: "a save of the show exactly where it is with all the settings and the output and everything", by "a shortcut button", to look at later ("look out later" = look at later; "the safe snapshot" = the saved snapshot: both INFERRED).
