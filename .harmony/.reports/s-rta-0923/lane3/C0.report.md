  required care to keep the STUB semantics honest: (1) `Grip::rank` (critic finding
  #3) is a bare field addition to `ParamConnection.h`, not a stub function — its
  *setting* behavior is explicitly left to C1 (`gripHeld()`/`gripTouch()`/`release()`
  keep their current bodies, unmodified here); I only added the declaration + a comment
  pointing at who implements the behavior, matching the critic's exact split. (2) Case
  (h) in `test_manual_write.cpp` needed rewording per critic finding #1 ("the twin is
  untouched" -> "the twin is NaN") — I implemented it against `ConnectionEngine::tick`
  (not a bare `evaluate()` call) specifically because finding #1's underlying bug lives
  in the *tick-level* per-scalar store (`tickScalars`'s `if (!std::isnan(y)) store(...)`),
  so only a tick()-level assertion can discriminate the fix from the no-op; a bare
  `evaluate()`-only test would pass today already (evaluate() already returns NaN while
  gripped — that part is pre-existing, unchanged behavior) and would NOT be fail-first
  proof of finding #1's actual defect.
- The probe script's teardown deliberately deviates from the plan's own §6.3 wording
  ("quit gracefully via osascript, never pkill") because THIS dispatch's builder-rules
  packet explicitly overrides it ("it must pkill the app at the end only after
  confirming no output window was opened"). I read the packet as authoritative over
  the plan text for this one procedural detail (both instructions agree on the
  SCREEN-SAFETY LAW's actual invariant — 0 windows ever on screen — they differ only on
  the termination *mechanism*), and implemented: confirm 0 Audio-DNA windows in the
  full CGWindowList first (a PASS/FAIL oracle in its own right), THEN `pkill`. Flagging
  this explicitly in case Harmony intended the plan's osascript wording to win instead.
- Oracle B in the probe script implements critic non-blocking finding #7 in full: a
  mean-luminance floor (`hi >= 0.02`) in addition to the ratio check, and captures are
  taken on an *observed 0<->1 transition* (previous sample past one threshold, current
  sample past the other) rather than a single polled sample at either extreme — this
  removes both of finding #7's named failure modes (the vacuous md5 clause on a
  stateful animated source, and the race between polling `/api/composition` and
  `render_frame` straddling the level's edge).
