## What changed

Implements addendum 4a from `.harmony/specs/s-rta-0923-review-fixes-plan.md` lane L3
("close-and-reopen", the plan's chosen design over an idempotent no-op — a grip
change held→decaying is the one legitimate reason for a re-touch, so swallowing it
would be wrong).

- `src/recording/PerformanceRecorder.h`: added a private helper declaration
  `void finishGesture(const ControlPath& key, OpenGesture& og, const ClockStamp& stamp);`
  (comment documents it as the shared exact-end logic used by `release()`, `stop()`,
  and `touch()`'s double-touch close — does NOT erase from `openGestures_`, callers
  do). Updated the `touch()` doc comment to describe the new close-on-re-touch
  behavior.
- `src/recording/PerformanceRecorder.cpp`:
  - New `finishGesture()`: the exact-end-breakpoint-append + move-into-`take_.lanes`
    logic, factored out of the old `release()`/`stop()` bodies (behavior-preserving
    extraction — same code, same order of operations).
  - `release()` now calls `finishGesture()` then erases the map entry (previously
    inlined the same logic).
  - `stop()`'s per-entry loop now calls `finishGesture()` per open gesture (same
    `clock_ != nullptr` stamp guard preserved), then clears the map once at the end
    (previously inlined the same logic per entry).
  - `touch()`: after reading `stamp = clock_->now()`, if `key` already has an open
    gesture, calls `finishGesture()` on it (closing it exactly at the current stamp,
    "as release() would") and erases it from `openGestures_` BEFORE constructing and
    inserting the new `OpenGesture`. Previously this case unconditionally overwrote
    `openGestures_[key]`, silently discarding every captured breakpoint of the
    still-open gesture.
- `tests/test_recorder_double_touch.cpp` (NEW): one `TEST_CASE`, tag
  `[performancerecorder][doubletouch]`, reproducing the plan's exact scripted-clock
  sequence: `touch(k,"held")@0.0`; `set 0.1@0.1`; `set 0.5@0.3` (both outside the
  50ms coalescing window); `touch(k,"decaying")@0.4` with NO preceding `release()`;
  `set 0.9@0.5`; `release()@0.7`; `stop()`. Asserts `lanes[k].gestures.size() == 2`,
  g0 (`"held"`) has 3 pts/3 stamps with `pts.back().y == 0.5f` and
  `stamps.back().t == Approx(0.4)`, g1 (`"decaying"`) has 2 pts
  (`0.9` + synthesized end) with `stamps.front().t == Approx(0.5)`, and seqs are
  strictly increasing across g0 then g1.
- `tests/CMakeLists.txt`: appended ONE self-contained block at the END defining a
  NEW standalone target `test_recorder_double_touch` (source list mirrors
  `test_take`'s minus `Program.cpp`/`Player.cpp`, which this test never needs —
  Composition/Clip/Layer/EffectLibrary/Effect for the data model,
  TempoMap/PerfState/Take/RecorderClock/PerformanceRecorder for the recorder core).
  **Deviation from the plan's L0 design, disclosed:** the plan's L0 (test
  scaffolding lane) was meant to land an empty stub `.cpp` inside the existing
  `test_take` target's source list first, so every fix lane would just add
  `TEST_CASE`s to that stub. L0 had not run in THIS isolated worktree (each lane
  builds in its own worktree per the harness's BUILDER RULES, and this worktree's
  `tests/CMakeLists.txt` still only has the pre-L0 shape). Rather than edit the
