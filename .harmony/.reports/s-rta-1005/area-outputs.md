## 1 TODAY -- what the app does in my area now (VERIFIED unless marked)
=====================================================================
Outputs (screens)
1. The Output menu (src/ui/MenuBarModel.cpp:134-150) lists one tickable item per connected display, titled "Display N (WxH)" or "Display 1 (WxH, main)" (src/output/OutputMenuModel.h:25-29); a tick = a window is live on that display; a click toggles it.
2. Below the displays: "All Outputs Off" (shortcut text Cmd+Shift+Esc) and "Restore Last Outputs" (OutputMenuModel.h:31-33); then, in the menu only, "Snapshot", "Start Recording", "Stop Recording" and "Syphon Output" (MenuBarModel.cpp:140-150).
3. The top bar button reads "Outputs: Off" or "Outputs: N" (OutputMenuModel.h:78-81; tooltip "Show the composition on displays: tick one or more (Cmd+Shift+Esc turns all off)", TopBar.cpp:276); it opens the SAME list as a popup (one item list, two doors; integration.md:25).
4. An output is one borderless window per display, the main display included, at normal window level, and it can never take the keyboard (Pitfall 40; integration.md:23-26).
5. The window shows the composition canvas, letter / pillar-boxed, never stretched; on a display of another size it is a scaled blit (FO Q4 step 10, 14).
6. The output shows the newest finished frame; the code states "+1 frame of latency by design"; no delay of any kind exists (grep "delay" in src/output and OutputWindow: no hit; FO Q6 final paragraph).
7. There is no per-output setting of any kind and no properties window: an output is a window plus a six-value fingerprint {x, y, w, h, scale, isMain} (OutputManager.h:99-103; OutputTargets.h:15-27). JUCE gives no display id or name (FO Q1; VERIFIED there at JUCE 8.0.4).
8. Keys: Cmd+Shift+Esc closes every output; Cmd+` raises the app window above an output; Cmd+F toggles the output on the main display; plain Esc is swallowed and touches no output (MainComponent.cpp:4087-4089 classifyOutputKey; integration.md:26). Cmd+F and Cmd+` need Shift up.
9. Hot-plug: an output whose display is unplugged closes and comes back by itself when that display returns; a display that moves or changes mode keeps its output (integration.md:28).
10. The wanted set of screens (fingerprints only) is saved in settings.json "outputs" on a change only; quitting writes nothing; the app NEVER opens an output by itself at launch or on opening a show; only Output > "Restore Last Outputs" does (integration.md:27, 29; MainComponent.cpp:7277-7278 "the ONLY way the saved set opens").
11. "All Outputs Off" closes the windows and cancels pending hot-plug reopens but leaves saved targets in the file (OutputManager.cpp:125-135, re-read by me; a manual close of ONE display removes its saved target).
12. Outputs are machine state, never show state: a show never opens or remembers an output (integration.md:27; the old `outputDisplay` key is dead).
13. While the preview panel is hidden (the big signal bar open) or the app is minimised, the main GL context goes away and every output keeps the LAST frame, frozen, not black (SharedFrameSet.h:7-11; MainComponent.cpp:2720-2723; Pitfall 40).
14. Dead menu ids exist with no item or handler: kOutputWindowed, kOutputIdentifyDisplays, kOutputTestCard (MenuBarModel.h:95-97; FO Q2).
Syphon
15. "Syphon Output" is a tick item in the Output menu; it is OFF at every launch and not remembered (SyphonOutput.h:61 `enabled_{false}`; integration.md:21). It is NOT in the per-display list, and NOT counted by "Outputs: N" or switched off by "All Outputs Off" (OutputMenuModel.h list holds displays only; closeAll closes windows only; INFERRED for Syphon from the absence of any Syphon call in closeAll).
16. When on, it publishes the finished canvas once per frame at canvas size through the main GL context (Renderer.cpp:893-894, 2576-2599). It has no setting (no delay, opacity, colour).
17. The Syphon server object is created when the main GL context is created, whether or not the item is ticked ("server announces at boot (eager -- Boris taste ruling pending)", APP-INVENTORY.md:35; Renderer.cpp:290; SyphonOutput.mm:128-143). 25. Composition transform
27. The inspector's Composition tab, section "Transform", has five controls: "Position X", "Position Y", "Scale", "Rotation", "Anchor" (CompositionInspector.cpp:160-164). It is applied to the whole canvas after the effect chain, before master opacity, and the pass clears the canvas to opaque black first (Renderer.cpp:773, 2498-2504).
28. Position is a pixel offset in a FIXED 3840x2160 reference space whatever the canvas size (slider = (v-0.5) x 3840 / x 2160; CompositionInspector.cpp:166-167; Renderer.cpp comment "reference 3840x2160 canvas"). Scale 0 to 200 %. Rotation (v-0.5) x 720 degrees.
29. The "Anchor" slider writes only the X anchor and forces Y to 0 (CompositionInspector.cpp:168-170), and the whole pass is skipped while position, scale and rotation are default, anchor not counted (Renderer.cpp:2484-2487): moving Anchor alone changes nothing on screen (INFERRED from those two reads; not run).
30. Transform values are saved with the show (Composition.h:770-775).
Other
31. Master opacity (one knob, top-right fader linked) dims the whole canvas, so it also dims preview, outputs, recordings and Syphon (BD:545 section; Renderer.cpp:795-815).
32. The Eyes / test harness has outputs-only hooks (`set_output_tap`, `output_probe`, ...) so no gate opens a window (FO Q8); the SCREEN-SAFETY LAW (BD:137-147) forbids unattended output-window drive.
