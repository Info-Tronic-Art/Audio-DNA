## 2. SEAT ATTACKS AND RULINGS

### 2.1 coreaudio seat

- CA-A1 [MUST] AdoptInput has no progress guard; it can loop every 10 s on unrelated scans. ACCEPT -> AM12.
  VERIFIED on the plan's prototype (E7: 11 re-applies from 10 hidden-device list changes). One sub-claim is wrong: rate
  pairing never leaves the input empty. When no in / out pair validates, JUCE keeps the default names (ADM:582-588), so
  "no input after an adoption" means the OPEN failed, and the plan's restore then leaves it output-only.
  This supersedes my earlier X-CA11 rejection of content keying and AM10's R16. The earlier rejection was about keying
  EVERY action on content (that breaks R4 / R4b, TDP:841-889). AM12 is narrower: it applies only to AdoptInput, only
  after a re-apply that ended without an input, and it is cleared by any change in the allowed inputs. R4 / R4b are
  untouched (E8: 36/36).
- CA-A2 [MUST] the reconciler may act on a stale snapshot on top of JUCE's own re-init. REJECT the fix; ACCEPT the test
  (M5r, AM15).
  Why nothing is stale: the timer reads the device and setup live when it fires. The scan it reads is the list JUCE
  re-inited against, because the guard rebuilds before JUCE's listeners run (DG:65-69). Every start / stop re-arms the
  settle (ADM:1088, :1091-1093), and so does the end of JUCE's own list handler (ADM:193-233).
  Why the fixes are worse: "rescan before evaluating" advances scan.seq on every evaluation (DG:94), which dissolves the
  once-per-scan gate -- every failing state would retry on its own change messages. "Act only if the device predates the
  lists" would suppress exactly the case AdoptInput exists for (JUCE's XML re-init lands output-only while a mic is
  listed).
  M5r is VERIFIED on both 655d232 and proto2: 0 re-applies, and exactly one JUCE start on top of JUCE's XML-branch re-init.
- CA-A3 [MUST] InputLost rests on INFERRED I1 / I2 and can misfire. REJECT opt-in / a watchdog / a B2 gate; ACCEPT the
  seat's own alternative (detect the dead combiner directly) as an ADDITION -> AM13 + AM14.
  Why I4 still ships:
  - Opt-in would leave V10's permanent deafness in production.
  - The <= 2 s stall is the close JUCE's own output-unplug re-init already performs on a dead device (ADM:219-229,
    CA:734-757).
  - "Newly hidden" is intended: an aggregate that gains a Bluetooth member must not stay open.
  - Renames come from JUCE's duplicate-name numbering and are named in AM19 R12.
  Why the liveness row is needed: it closes the case the name rule cannot see -- a re-plug inside the settle (E7 R16) --
  and the old R12 corner.
- CA-A4 [SHOULD] C3's teeth are thin; the setup diff is unexplained. ACCEPT IN PART -> AM16:
  - AE2 lint: catches a re-open guarded by `getCurrentAudioDevice()` (E11).
  - M8 gets a hidden-default fixture (the "launch with a default-hidden device, one open" ask).
  REJECT the TDP replica of setSourceMode: it tests a copy, not AudioEngine, which has no mock seam (plan F4(b)).
  REJECT "log the diff": the diff is established. A mono mic's requested 2-bit input mask differs from its active 1-bit
  mask (ADM:735-738 against ADM:185-189); a stereo mic is an early return (earlier ruling X-GP7 / AM11).
- CA-A5 [SHOULD] restore path. ACCEPT IN PART -> AM15 R14. R14 exercises the still-listed filter, which no planned case
  did; E9 shows the no-filter mutant FAILS it ("No such device", ADM:764-772).
  REJECT the aggregate-specific case: the restore reads only the post-filter lists, and the aggregate member rule is
  dp::classify's, already covered by TDP P3 / P3b (TDP:302, :323).
  REJECT "do not count the restore against the bound": the restore sits inside the one re-apply, and lastReapplyMs_ is
  set once, before the open (plan I3 pseudo-code).
- CA-A6 [SHOULD] timer starvation; a late default swallowed. REJECT.
  Starvation: restarting the settle on every change message is main's merged semantics (DG:153-163). A continuous
  stream needs JUCE restarting a device itself or a flapping device list; acting mid-stream adds a close / open to an
  unstable set. R1 / R13 pin one action after the burst.
  Late default: a mic in the launch scan was a launch candidate (ADM:587-588). An output-only launch means no allowed
  input, or a failed open (then R10). A default flip never rescans (CA:2122). "Rescan on the timer" breaks the scan gate
  (DG:94).
- CA-A7 [NIT] wording overclaims HAL coverage; make B2 a release precondition for I4. ACCEPT the wording -> AM18.
  REJECT the precondition: B2 needs a wired mic this rig lacks, and until then the choice is shipping I4 vs keeping
  today's deafness.

    mode dead.

    mode, and deferring to the switch puts a device path back into setSourceMode (C3, AE2).
  - The file transport resamples by source rate (AE:64-65), and analysis by device rate (R13's AnalysisResampler).
  - Cost kept: one restart per deliberate plug, <= 1 per 10 s (AM10 R15).

  a longer settle / shipping only after B2; ACCEPT the labels (AM18). The premise gap is closed by AM13.
  - A name absent past the settle means the HAL device object is gone, and the combiner's input died with it
    (CA:1118-1127). That re-apply is not a switch away from a working input.
  - A LONGER settle widens the window in which a re-plug re-lists the name while the combiner stays dead -- the exact
    deaf case E7 R16 shows.
  - Renames (two identical mics): AM19 R12.
- G-A3 [MUST] silent swap at a gig. ACCEPT -> AM17. When a re-apply replaces a lost mic by another, the persistent
  notice names both mics, in both source modes. Q2's default becomes "the note".

  B2(d) shows Boris). REJECT the extra informational label: whether the app should switch at all is Q1's decision, and a
  hint built for a default Boris may overturn is premature (AM21 lets Harmony add it after Q1).
- G-A5 [SHOULD] a re-apply during a take / recording. REJECT.
  - A same-rate restart continues the take; a rate / channel change self-stops the tap cleanly, never writing a

  - This is tested: test_recorder_host.cpp:874-908, test_bt_device_shapes.cpp:273-310, test_audio_store.cpp:913-932.
  - The record panel reports it (test_record_panel_model.cpp:614, :634). Video recording carries no audio
    (VideoRecorder.h:34-35).

  - Named as AM19 R19.

  AE2. REJECT the mock replica (as CA-A4). REJECT the probe ordering assertion: ADM:971-985 delivers a synthetic
  audioDeviceAboutToStart when the callback is added after the open, and the real start delivers it when added before --
