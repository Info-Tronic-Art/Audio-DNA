# attack-tsan-realtime (REAL-TIME / LIVE-SHOW seat) -- verdict AMEND
Design (one 16-byte CAS word per layer, render one attempt) is sound for latency; defects are in the give-up path, the post-CAS tail, test teeth and scope.
MUST-none outright; top SHOULDs:
1 [SHOULD] T3 "give up after 4 attempts ... self-healing" is false for bar-snapped pending triggers. Layer.h:292-328 fires only when beatInBar==0 (Bar/TwoBar/FourBar); a render-side processPendingTrigger that gives up leaves the trigger pending to the NEXT qualifying beat = a whole bar (up to 4 bars) late. Fix: on exhausted attempts retry within the same frame (bounded loop of 16, contention is message-thread-only) or keep the beat edge latched until applied.
2 [SHOULD] Clip-state tail after the CAS (T2 step 3) is a second, non-atomic tuple. Today Layer.h:276-286 has the same order, but the plan sells "one consistent tuple"; the render can load new active with old playing/playhead for one frame (first activation: frozen first frame). Also if an autopilot CAS moves the layer again before step 3, the tail rewinds playhead of a clip now `previous` mid-fade (visible jump). Fix: apply tail only if the layer tuple still equals t.after, else skip; or do the tail BEFORE the CAS for new activation (clip not yet visible).
3 [SHOULD] Momentary release (MainComponent.cpp:7590-7595, 7628-7633) gates clearActiveClip on active==column, so a pad released before its quantized trigger lands never clears the pending trigger; it fires on the beat and latches a clip after the finger is up (defeats the L5 comment at Layer.h:338-349). Plan T2 "clearActiveClip(resolvedColumn) only if active==col" preserves the bug. Fix: one CAS that clears if active==col OR pending==col (still parity-safe for every other path). At minimum file it.
4 [SHOULD] G3 GREEN can be vacuous for the render-thread writers. Autopilot triggers/beatsPlayed/processPendingTrigger only run on beat edges (Renderer.cpp:547/772 cited by plan); scen.py (tsan-harness/scen.py:72-75) switches audio mode file/input, but nothing in scenario d enables layer autopilot or verifies beats are detected (beat-snap clip + PlayNext autopilot need totalBeatCount advancing). Require d to enable autopilot on >=1 layer, play a beat file, and assert via /api/state that a snapped trigger actually fired; else the render-trigger half is covered only by R1.
5 [SHOULD] "One load per layer" (the consistency + G5 latency invariant) is enforced only by reviewer grep (T3 risk). A stray second runtime()/getActiveClip() ships silently. Add a test hook (debug counter of runtime() loads per layer per compositeDeck, or a lint over compositor loop bodies) so it can fail. R1's post-join "range checks only" cannot detect a torn tuple on the lane; add an invariant checked render-side (previous!=active, progress in [0,1], previous>=0 iff progress<1) accumulated into an atomic violation counter asserted after join.
6 [SHOULD] Retrigger-restart parity has no test. playheadPosition lost update (render store at Renderer.cpp:1823 vs model store Layer.h:268/282) stays by design; T4 only CASes `playing`. Plan's "cannot lose a restart that was ISSUED" is INFERRED (VideoPlayer unread). Column retrigger, non-active-deck retrigger and autopilot same-column retrigger do not restart (plan admits). Add a FakePlayer test for the seek-then-write-back ordering, and a probe row in G4 for retrigger restart on the active deck.
7 [SHOULD] Goal says "race-free"; R5 leaves the whole config-scalar class (Clip speed/in/out/loopMode/beatSnapMode, Layer transitionSpeed/blendMode/visible/bypassed/solo, effect params, macros) plain. These are exactly what a performer drags live. The sweep passes only because scenario d does not move them. Either widen d with set_param/set_clip_* so RED/GREEN is honest, or re-label the goal as "5 observed families".
8 [SHOULD] Render-cost gate is INFO-only (G6). 23 manual fields + 4 clip fields + 16-B acquire loads are cheap, but nothing gates a regression. Give G6 a soft bar (median peak_frame_time_ms within +0.3 ms of main) even if not blocking; also confirm ADNA_SANITIZE-off builds inline the 16-B atomic at -O0/Debug (is_always_lock_free static_assert covers it; verify a Debug build links without libatomic).
9 [NIT] R1 test loops call UndoManager::perform on a thread while tail writes run; Catch2 REQUIRE off the main thread is unsafe: plan says post-join only, keep it explicit.
10 [NIT] T0 RED relies on TSan seeing the pair; accept UB crash as RED is fine but then "at least one data race with src/ frame" bar (G2) would mark that case invalid; state the exception in the bar.
11 [NIT] hasActiveLayers (CompositorEngine.cpp:1049) loads separately from the per-layer load; a trigger between them shows a layer drawn empty for one frame. Pre-existing; note it beside R11.
12 [NIT] setRuntime (release store) used by undo/routine restore can clobber a concurrent trigger's pending; acceptable but document that restore is last-writer-wins.
Strongest counter to my position: the design is already zero-latency and lock-free, the gaps are edge cases (4 consecutive CAS failures needs 4 message-thread writes in microseconds). I still hold AMEND because item 1 turns a microsecond race into a bar-late trigger, and items 4-5 mean the gates as written cannot fail for the render-thread half.
