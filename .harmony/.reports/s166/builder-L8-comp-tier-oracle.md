### ENDPOINT SHAPES (the deliverable — exact, for gate-writing)

**POST /api/add_global_effect**
Request: `{"name": "<effect name>", "enabled": bool (optional, default true), "dryWet": float (optional, default 1.0), "params": {"<paramName>": float, ...} (optional)}`
- `name` missing/empty → 400 `{"ok":false,"error":"Missing 'name' field"}`
- unknown `name` (no `EffectLibrary::getEffectDef` match) → 404 `{"ok":false,"error":"Effect not found: <name>"}`
- **GL context not attached (fix round 1) → 503 `{"ok":false,"error":"Renderer not attached (no GL context — cannot safely mutate globalEffects)"}`, globalEffects untouched.** Before this fix the handler silently returned `200 {"ok":true,"index":-1,...}` without ever adding the slot — a fabricated success caught by the independent reviewer.
- unmatched keys inside `params` are silently skipped (matches this file's `handleSetEffect` / ApiServer's `handleSetParam` convention) — counted in `matched_params` so a caller can tell.
- Success 200: `{"ok":true,"index":<int, new slot's position>,"name":"<name>","matched_params":<int>,"num_global_effects":<int>}`
- New slot: `enabled=<given or true>`, `bypassed=false`, `dryWet=<given or 1.0>`, `paramValues` = `EffectLibrary` defaults for `name`, then any `params` overrides applied by name.

**POST /api/remove_global_effect**
Request: `{"index": <int>}`
- missing `index` → 400 `{"ok":false,"error":"Missing 'index' field"}`
- **GL context not attached (fix round 1) → 503 `{"ok":false,"error":"Renderer not attached (no GL context — cannot safely mutate globalEffects)"}`, checked before the out-of-range check so a detached context is never misreported as a bad index.**
- out of range (`< 0` or `>= size`) → 400 `{"ok":false,"error":"Index out of range: <index>"}`, vector untouched
- Success 200: `{"ok":true,"removed_index":<int>,"num_global_effects":<int, post-removal size>}`

**POST /api/set_global_effect_bypass**
Request: `{"index": <int>, "bypassed": <bool>}` — both fields required.
- missing either field → 400 `{"ok":false,"error":"Missing 'index' or 'bypassed' field"}`
- out of range → 400 `{"ok":false,"error":"Index out of range: <index>"}`
- Success 200: `{"ok":true,"index":<int>,"bypassed":<bool>}`

**GET /api/global_effects**
Response 200: `{"global_effects": [ {"index":0, "name":"<effectName>", "enabled":<bool>, "bypassed":<bool>, "dryWet":<float>, "params": {"<paramName>": <float>, ...}} , ... ], "count": <int>}`
- `params` keys are the real param names resolved via `EffectLibrary::getEffectDef(name)`; if the effect def can't be resolved (shouldn't happen — every slot was validated on add) keys fall back to `"param0"`, `"param1"`, ...

**POST /api/set_composition_params**
Request: any subset of `{"masterOpacity": float, "masterSpeed": float, "compOpacity": float}`.
- none of the three keys present → 400 `{"ok":false,"error":"No known field provided (expected masterOpacity, masterSpeed, and/or compOpacity)"}` (prevents a silently-no-op'd call)
- Success 200: `{"ok":true,"masterOpacity":<float>,"masterSpeed":<float>,"compOpacity":<float>}` — echoes ALL THREE current values (not just the ones set), so this doubles as a partial readback.

**GET /api/composition_params**
Response 200: `{"masterOpacity":<float>,"masterSpeed":<float>,"compOpacity":<float>,"decks":[{"deck":0,"layers":[{"layer":0,"clips":[{"column":0,"clipOpacity":<float>}, ...]}, ...]}, ...]}` — `clips` array only contains occupied cells (mirrors `ApiServer::handleComposition`'s `has_value()` filtering).

**POST /api/set_clip_opacity**
Request: `{"layer": <int>, "column": <int>, "clipOpacity": <float>}` — all three required.
- any missing → 400 `{"ok":false,"error":"Missing 'layer', 'column', or 'clipOpacity' field"}`
- no active deck, or no clip at that layer/column (empty cell or out of range) → 404 `{"ok":false,"error":"Clip not found at layer <L> column <C>"}` — NOT a silent 200 (this was the one place a naive implementation would produce the silent no-op the packet warns about).
- Success 200: `{"ok":true,"layer":<int>,"column":<int>,"clipOpacity":<float>}`

### RISKS
- **CORRECTION to this section's original text (fix round 1):** the original version of this RISKS entry claimed a detached/stalled GL context would make `handleAddGlobalEffect`/`handleRemoveGlobalEffect` "block indefinitely." That was wrong, and the independent reviewer traced why: JUCE's `OpenGLContext::execute()` (vendored `juce_OpenGLContext.cpp:694`) only constructs and blocks on a `BlockingWorker` when a `CachedImage` exists; with none — the exact state `previewPanel_`'s context enters when hidden or zero-sized, per this repo's own `isAttached()` guards at `Renderer.cpp:823,890,924` — it takes an `else jassertfalse;` branch that, in a Release build, is a silent no-op: `executeOnGLThread` returns immediately, the queued lambda never runs, and the handler was returning a FABRICATED SUCCESS (`200 {"ok":true,"index":-1}` with `globalEffects` untouched), not hanging. This is now fixed (see FIX ROUND 1 above and the updated endpoint shapes) with an `isAttached()` guard returning 503 before the fence in both handlers. Recorded here per the team lead's instruction that a wrong risk note is worse than none — the corrected risk is the one below.
- **Risk (residual, low):** the `isAttached()` guard is itself a check-then-act read — `Renderer.cpp:818`'s own comment on the identical pattern acknowledges a narrow TOCTOU window where the context could detach between the check and the `executeOnGLThread` call. Severity: low — this is the SAME acknowledged, accepted narrow window as the 3 pre-existing `isAttached()` sites in `Renderer.cpp`, not a new one I introduced, and it converts what would otherwise be a guaranteed fabricated-success into a rare race that (per JUCE's own `else jassertfalse` branch) at worst reproduces the pre-fix behavior on that one call. No mitigation beyond what the existing precedent already accepts.
- **Risk:** `set_global_effect_bypass`/`set_composition_params`/`set_clip_opacity` are unfenced scalar/bool writes into fields the GL thread may read unsynchronized (bypass: read every frame today via `CompositorEngine.cpp:250-252`; the 3 scalars/clipOpacity: read by nobody yet). Severity: low today (matches EffectChain's own documented DEFERRED BOUNDARY gap) but will need revisiting the moment a future lane wires the 4 scalars into the renderer — flagged explicitly in both the code comments and this report so that lane doesn't miss it.
