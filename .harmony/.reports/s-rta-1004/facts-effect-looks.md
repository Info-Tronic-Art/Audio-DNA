### Q1 WHERE EFFECTS LIVE

**Answer.** There is ONE struct for an effect instance, `Clip::EffectSlot`, and exactly three places hold a `std::vector<Clip::EffectSlot>`: a clip (`Clip::effects`), a layer (`Layer::layerEffects`, the SHARED layer stack since lane bf9b) and the composition (`Composition::globalEffects`). The UI and the undo code address them with a three-kind `EffectScope`. A slot stores the display name, the param values by POSITION, dry/wet, enabled, bypassed and its connections. The library gives names, uniforms and default values only; there is no min / max / unit anywhere.

### Q2 WHAT ELSE SHAPES AN EFFECT'S LOOK

Everything else asked about is either not an effect property (autopilot, macros' own state, signals) or lives only on the hidden legacy chain (beat-synced randomise, legacy mappings). The ONE connection type is the same for effects, sources, macros and clip / layer / composition scalars.

## 3 WHAT A PLANNER MUST NOT ASSUME
---------------------------------------------------------------------------------------------------------

1. **"Effect name = shader key."** The slot holds the DISPLAY name; `Clip.h:62` still says "Registry name (e.g., "ripple")" -- the comment is wrong (Pitfall 1). test_composition.cpp's fixtures use "ripple" lower-case but only as an opaque string.
2. **"A look can name its params."** The show stores param values as a bare positional array (Clip.cpp:108-111). Adding, removing or reordering a library param silently shifts every saved value, and nothing reconciles effects at load (sources ARE reconciled by uniform name, CompositionLoad.h:100-104). The legacy preset code restored by name for exactly this reason (test T8). A look keyed by index would break the same way; the library is the only place that gives names. Takes and routines are also positional (PerfState.h:23-31).
3. **"The library has ranges."** It has none (EffectLibrary.h:17-34): name, uniform, default only. "Min / max" means 0..1.
4. **"Every effect has a stable unique identity."** The vector index is the only key: bindings (`targetEffectIndex`), takes (`fx` index), routines, REST (first slot of that NAME) and undo scopes all address by index or first-name. Two instances of the same effect on one clip cannot be told apart by name (ApiServer.cpp:650-665). A reorder does not exist, so indices change only on add / remove / undo.
5. **"There is one add path."** There are four (Q1d); two of them (deck-cell drop, layer-strip drop) never touch EffectStackView, and the deck-cell drop can create a brand-new FX-only CLIP. A look applied "when an effect is added" would have to hook all of them.
6. **"Param edits are undoable."** They are not (Q7). Only add / remove / bypass are. Boris's rule "an effect put on a layer or a clip IS undone" covers the structural step; a look load is a NEW kind of edit with no precedent, and the "Undo never changes the layer strip" filter is not built yet.
7. **"Writing `paramValues` is enough."** Pitfall 33: the renderer reads `effParam(i)`; the engine publishes `paramLive`; a connected param ignores the manual value until its grip releases. A look that sets a value on a CONNECTED param changes nothing visible (the engine keeps winning), and a look that carries connections replaces the user's connection setup. Also: append params ONLY with `EffectSlot::addParam` (never `paramValues.push_back`), and `forgetConnection()` on every bound row before any erase / rebuild.
8. **"`enabled` is the on/off switch."** The UI toggles `bypassed`; `enabled` has no UI writer; a file written before `enabled` existed has no key and `static_cast<bool>(void)` reads false (Clip.cpp:285) -- INFERRED, UNKNOWN-NEEDS-A-RUN (load a hand-edited show whose slot lacks "enabled").
9. **"The right-click on an effect header is free."** It currently folds / unfolds (EffectStackView.cpp:456-460 has no button test). A menu on right-click changes that behaviour; the header has no free room (name is full width; collapsed value and arrow sit under the X button).
10. **"The drop highlight is cyan."** CLAUDE.md's UI rule says cyan border + 15 percent fill; EffectStackView paints purple 0xff8866cc (EffectStackView.cpp:13-16). The code and the rule disagree.
11. **"Global effects are not read by the GL thread."** `core/EffectCommands.h:57-62` says so ("verified -- grep across src/render/") but `Renderer.cpp:706-714` DOES render `composition_->globalEffects`. The comment is stale; the fence is applied unconditionally anyway.
12. **"UndoManager is dead."** docs/claude/architecture.md:265 still says "DEAD: perform() never called; undo/redo keys are no-ops"; the code uses it everywhere (MainComponent.cpp:4051-4065, 5323-5338). The doc is stale.
13. **"Beat-synced randomisation / per-type autopilot / OSC effect params change the effects on the clips and layers."** None does: randomise and OSC `/audiodna/effect/...` act on the hidden legacy chain (Pitfall 28 is the same split for Eyes); autopilot changes which CLIP plays.
14. **"The old Save / Load / FX Save hold clip effects."** They hold the hidden legacy chain (facts-one-save Q6 + its VERIFICATION). Removing them does not touch any clip / layer / global effect; but `EffectsRackPanel::refreshFromChain` and the legacy chain stay in place. Their folder `~/Library/AudioDNA/FX Saves/` is empty on Boris's disk; `Presets/` holds 4 old files (facts-one-save).
15. **"settings.json is safe to extend blindly."** `readRoot` treats an unreadable or non-object file as empty and the next `update` writes only its own key (facts-saves trap 8; AppSettings.cpp:19-28, 32-38). Two writers exist today ("outputs", "milkDropPresetDir"); no failure message is shown for either.
16. **"One app-data folder."** Two spellings coexist (Q5). A looks file placed beside settings.json (`Audio-DNA`) is NOT beside the compositions (`AudioDNA`). APFS is case-insensitive by default, so only the HYPHEN matters; `Decks` (legacy) vs `decks` collide on a case-insensitive volume (INFERRED).
17. **"The ISF-imported effect reaches the stacks."** It registers in the Renderer's library, the UI uses MainComponent's (Q1c); ISF "doesn't render". Treat imported effects as outside a look's scope (INFERRED).
18. **Pitfalls that bind this area, by number:** 1 (display name vs shader key), 5 and 8 (ResettableSlider + `setDefaultValue`), 13 (temporal effects need two render paths), 16 (multi-select drop), 17 / 27 (effect defaults must be noticeable and visible on first add: a look's default content is a user-visible default), 19 / 35 (frame-history effects; GL history keyed by the shared layer), 28 (Eyes `set_effect` drives the legacy chain, so Eyes cannot verify a clip / layer look), 33 (engine-driven rows), 36 (clip ids re-minted on Duplicate), 45 (every registered param is read by its shader), 57 / 59 (timer-driven repaint / model-driven widget change test, if a menu label shows the current look), 58 (a load is staged: a command during the window acts on the LIVE composition), 63 (shared fields `Relaxed<T>`; effect params / dryWet are NOT yet atomic), 67 (shown deck = grid, never the screen). CLAUDE.md rules: PopupMenu must use `showMenuAsync()` with `.withParentComponent(getTopLevelComponent())`; every slider is a `ResettableSlider`; every stack inspector is a `DragAndDropTarget`; docs must be updated with the change.
19. **Scope of "a look belongs to ONE effect" vs the data model.** An `EffectSlot` also carries dryWet, bypassed and connections. Which of these a look holds is NOT decided by any code or ruling I read; the facts are in Q1b and Q2 (connections are inside the slot and travel with a whole-slot copy; grips never do).
