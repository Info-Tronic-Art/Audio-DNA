## 1 QUESTIONS ANSWERED

### Q1 Screen Delay: unit, range, step, what is delayed, negative, purpose, frame-based, cost
Answer: Unit milliseconds. Range 0 to 100 ms per screen. Negative: not offered (range starts at 0). Purpose per Resolume: absorb small delays the signal chain adds AFTER the picture leaves Resolume (projector, LED processor, cables). Step, frame-based, cost: not stated.
- DOCUMENTED (Screens page, "Adjusting Delay"): https://resolume.com/support/en/screens -- "Each screen can have a delay between 0 and 100 ms, to account for small delays introduced by the signal chain after the outputs leave Resolume." Version: current support page (Arena 7 site; the same section exists in /support/en/6/screens).
- DOCUMENTED (Arena 5 release notes, first appearance): https://resolume.com/blog/12462 -- "NEW - Screen output delay compensation". Version Arena 5 (2015).
- Screenshot (Boris's, Arena 7.x): Delay row reads "0 ms" with a slider whose marker sits at the LEFT end (consistent with a 0..100 ms range, 0 at left; Opacity marker at right end for 100 %).
- Per screen, picture only: DOCUMENTED wording is "Each screen can have a delay ... to account for small delays ... after the outputs leave Resolume" = a property of one screen's output. Nothing says audio is delayed. The screen is the unit (not the slice, not the composition).
- "up to 6 frames": THIRD-PARTY (Oaktown, honorary member, 2017-02-04, Resolume 6 era) https://resolume.com/forum/viewtopic.php?t=14126 -- "at 60 FPS, 100 ms will allow you to adjust for up to 6 frames. You would need to identify the output that's the most delayed and adjust the other ones back to match it." Use: line screens up with each other by delaying the faster ones to match the slowest.
- STAFF (Zoltan, Team Resolume, 2024-01-30, Arena 7.17.3 thread) https://resolume.com/forum/viewtopic.php?t=23147 -- "Try connecting a monitor to the output and check the delay. If it's there it might be set in the Resolume advanced output, in the Screen setting. ... If it's in time there, the delay is added once the signal left your machine." (Pointing to the Delay as the Resolume-side knob.)
- Lining picture up with SOUND in a big room: the Screens page does NOT say this. Its stated purpose is signal-chain delay after the output. (see Q8)
- Frame-based under the hood: NOT DOCUMENTED. Only hint is the Oaktown "6 frames" sentence (not a statement about implementation). Settle in Arena: Advanced Output, real display screen, drag Delay to 100 ms; in the Screen row type 1, 2, 3 ms and see whether the on-screen picture moves in 16.7 ms steps (use a flashing test source + phone slow-motion) -- OR just see whether the slider accepts and displays 1 ms steps (the display says "ms", integer in the screenshot).
- Step size: NOT DOCUMENTED. Settle: click into the Delay value, type 7, then 7.5; see what it keeps.
- Cost (memory / performance) of a Delay: NOT DOCUMENTED for the Screen Delay. (Resolume DOES say Virtual Outputs cost "0 or 1 frame" of delay and Wire delay buffers "eat VRAM" -- different features: https://resolume.com/support/en/screens and https://www.resolume.com/blog?page=6 "do be careful with long delays because they eat VRAM for breakfast".) Settle: set Delay to 100 ms at 1920x1200 and watch Activity Monitor / Arena FPS (30 s).
- Bug history (DOCUMENTED, release notes Arena 6 beta fix list): https://resolume.com/blog?page=17 (Resolume 6 fix list) -- "9901 ASS Screen Delay>0 dims output when screen opacity !=100%" (ASS = Advanced Screen Setup). Shows the Delay is a Screen parameter inside the screen setup and once interacted with Opacity. Fixed in R6.

### Q2 Where the Delay is stored; how Advanced Output presets are saved/loaded
Answer: Resolume says the whole OUTPUT SETUP is a preset that is NOT tied to a composition. The Delay is a Screen parameter of that setup (INFERRED, not stated in one sentence), so it should travel with the Advanced Output preset, not the composition.
- DOCUMENTED https://resolume.com/support/en/advanced-output -- "It's possible to switch between different screen setups. Using the dropdown in the top left of the Advanced Output window, you can save and select different setups."
- DOCUMENTED same page -- "This also means that your output setup is not tied to a certain composition. You can use different setups with the same composition, and use different compositions with the same setup."
- DOCUMENTED same page -- "After saving, the preset can be found as an .xml file in the Resolume documents folder: Mac: Users/~/Documents/Resolume Avenue-Arena 5/presets/screensetup/" (stale folder name; on Boris's Mac the folder is ~/Documents/Resolume Arena/Presets/Advanced Output, VERIFIED present, empty). Also: "When loading a preset via the dropdown, it will be automatically copied to the correct folder in Documents." and "Choose Reveal in Finder or Explorer from the dropdown".
- Use case Resolume names: "weekly gigs at different venues that each require a specific setup".
- Sharing: copy the .xml to the same folder on another computer, load via the dropdown; works Mac <-> PC.
- Last-used setup pointer: STAFF forum (2016-10-31, thread t=13883 "corrupted screen setup xml file", reply author not captured in the excerpt) https://resolume.com/forum/viewtopic.php?t=13883 -- "remove the advanced.xml file ... This file just contains the location of the last used screen setup file". So the app remembers WHICH preset was last loaded in a small file, and loads it at start.
- Delay inside the preset xml: NOT DOCUMENTED directly. A posted Arena 5.0.1 sample xml (THIRD-PARTY, https://resolume.com/forum/viewtopic.php?t=12760, 2015-12-27) lists Screen <Params name="Output"> = Opacity, Brightness, Contrast, Red, Green, Blue but no Delay; that screen was a VIRTUAL screen, which has no Delay row (see Q4), so the sample neither proves nor disproves. The same thread carries a reply that the xml is "primarily for internal use" and its structure is not guaranteed between updates (author not captured). Release-note evidence that Delay lives in the screen setup: "ASS Screen Delay>0 ..." (Q1) and "Capture card output settings aren't saved in advanced output preset" (Arena 5.0.1 notes https://resolume.com/blog/category/software?page=7), showing per-screen output settings are saved in the preset.
- Settle in Arena (under a minute): Output > Advanced; on a real display screen set Delay 40 ms; save the setup via the top-left dropdown; Reveal in Finder; open the .xml in TextEdit and search "Delay". Then load a different composition and check the Delay still reads 40 ms.

### Q3 The other rows (Opacity, Brightness, Contrast, Red, Green, Blue)
Answer: Per-screen output corrections "to adjust mismatched outputs". Opacity 0-100 % (default 100). Brightness, Contrast, Red, Green, Blue are centre-zero sliders, range -1..+1 internally, default 0.
- DOCUMENTED https://resolume.com/support/en/screens -- "Each screen has Opacity, Brightness and Contrast controls, as well as individual controls for the Red, Green and Blue channels. You can use these to adjust mismatched outputs. For instance, you can dim the brightness on a LED panel while sending the undimmed output to a projector as well. Or you can remove some red from a projector..."
- Ranges: THIRD-PARTY (posted Arena 5.0.1 xml, https://resolume.com/forum/viewtopic.php?t=12760): Opacity default 1 range 0..1; Brightness, Contrast, Red, Green, Blue default 0, range -1..1. Matches the screenshot (Opacity "100 %" marker at right; others marker in the middle, shown as "0"). Shown units in Arena 7: Opacity in %, others bare number. Whether the displayed value is -1..1 or scaled: NOT DOCUMENTED (screenshot shows only 0).
- Meaning of Brightness vs Contrast maths (additive offset vs gain): NOT DOCUMENTED.
- Screen Device row: menu of connected outputs ("Display 2 (1920x1200)"): DOCUMENTED, same page: "The screen will show the output it's sending to under its name, as well as in the Device dropdown menu on the right." "Every output can only have a single screen associated with it."

### Q4 Which output kinds have a Delay
Answer: Real displays (connected monitors/projectors) have it. Virtual screens, NDI, Syphon/Spout showed NO Delay row (forum, 2019-2020, Resolume 6/7 era). Capture (playback) cards and DMX/Lumiverse: not documented for the Screen Delay; DMX has its OWN global output delay.
- THIRD-PARTY user report, Zoltan (STAFF) asking back, 2019-08-20 https://resolume.com/forum/viewtopic.php?t=16029 -- user: "In 'Advanced Output' I create a screen with NDI as Device ... If I plug a normal screen I'm able to see the 'delay' option, with Virtual Output/NDI/Syphon-Spout I'm not." Zoltan (Team Resolume) only linked the Screens page and asked "Which Resolume version are you using? Do you need NDI or do you need Output delay?" -- no staff denial or fix is in the thread.
- THIRD-PARTY 2020-05-27 https://resolume.com/forum/viewtopic.php?t=19798 -- a request: "Is there a way to access the delay feature shown when selecting 'Display 1, etc' in 'Advanced Output' such that it could work for NDI or Syphon/Spout?" No staff reply in the thread. (Whether Arena 7.22 changed this: NOT DOCUMENTED.)
- Virtual Outputs: DOCUMENTED https://resolume.com/support/en/screens -- "Depending on how busy things are, the delay will be either 0 or 1 frame." (an internal latency, not a setting).
- Capture / playback cards: DOCUMENTED they exist as screen devices ("Any connected cards that support playback will show up here as well. ... Output via playback cards is only available in Resolume Arena"); a Delay row for them: NOT DOCUMENTED.
- DMX Lumiverse: DOCUMENTED https://www.resolume.com/support/en/dmx -- "A Lumiverse has the same Opacity, Brightness, Contrast and Color options that a regular Screen has." (no Delay mentioned for Lumiverse) and "The delay determines the time between rendering the frame and outputting it to DMX (in milliseconds). This is used to keep lights/projectors in sync. The default value of 40ms ..." -- that is a DMX PREFERENCES setting, shared: "All universes share the same delay and framerate settings."; Arena 5.0.1 notes: "[NEW] Variable DMX output delay".
- Settle in Arena: Output > Advanced; add screens, set Device to NDI, Syphon, a virtual screen, and (if available) a capture card; note which show a Delay row.

### Q6 Other audio/video offsets in Resolume
Answer: Yes, several. (a) Clip Start Offset (general preference, ms). (b) Audio buffer size. (c) SMPTE per-clip frame "delay compensation" (negative allowed) and start offset. (d) An audio "Master Output Delay" preference is reported by third parties but is NOT on the official Preferences page. (e) DMX output delay. No offset setting is documented for Ableton Link or MIDI clock.
- (a) DOCUMENTED https://www.resolume.com/support/en/preferences (page shows version tabs "v 7.18 v 7 v 6") -- "The Clip Start Offset allows you to let a clip start an amount of milliseconds further into the timeline of the clip, to compensate for delays with MIDI triggering and/or long cable runs." STAFF (Resolume reply "fortune telling option", 2013, https://resolume.com/forum/viewtopic.php?t=10309): "you can set the clip start offset. This will make clips start a few millis further in their timeline, and from then on loop normally. This means that although you will miss a few frames on the first play, it should from then on be in sync." (author not captured; reply appears from the Resolume side).
- (b) DOCUMENTED same Preferences page -- "Higher buffer sizes will introduce more latency into the system ... 512 or 1024 are usually safe choices."
- (c) DOCUMENTED https://resolume.com/support/en/smpte -- "Optionally you can add an delay compensation in frames to account for any lag that may occur in the signal flow. Light travels faster than sound, so on very big stages the sound will take longer than the video to reach the majority of the crowd. A negative compensation can help with getting things perfectly lip sync again." and "You can select a starting timecode for a clip via the offset parameter." (SMPTE is Arena only.) <-- the only official Resolume sentence that names the large-room sound-lag problem; it is for SMPTE clips.
- (d) THIRD-PARTY only: tutorial https://btw.tools/how-to-use-timecode-with-ableton-resolume-arena-and-grandma2 -- "You can ignore the Master Output Channels, Master Output Delay, and Preview Output Channels for now"; forum user 2020 https://resolume.com/forum/viewtopic.php?t=19798 -- "in the PREFERENCES pull-down menu, under AUDIO there is the Master Output audio delay"; forum user 2017 https://resolume.com/forum/viewtopic.php?t=15098 -- "Setting the Audio delay under preferences to 300ms, syncs the videos with audio." The official Preferences page lists Output Device / Output Channels / Sample Rate / Buffer Size / Input / FFT / SMPTE / VST and NO audio delay. Range/unit: NOT DOCUMENTED. Settle: Arena > Preferences > Audio; look for "Master Output Delay" and its unit/range.
- Ableton Link: DOCUMENTED https://resolume.com/support/en/link -- "It will now automatically keep the BPM and the current position in the measure in sync between all connected computers." and "When using Link, the Resync and Pause buttons for the BPM are disabled. It's considered bad musical practice to do a hard reset of the measure like this, or completely pause the BPM altogether.". No offset control documented. STAFF Zoltan 2023-10-04 https://resolume.com/forum/viewtopic.php?t=22812 -- "Generally it's not recommended to change the beat position in link, but we're looking at how we could offer the option." (user in that thread: "As long as it is not possible to set a negative delay or clock a resync button, the function is not usable"). STAFF Zoltan (2023-12) https://resolume.com/forum/viewtopic.php?t=23012 -- "We don't want to send it out, that's why they are disabled when you have Link enabled" and "We have a ticket to figure out something about better flexibility."
- MIDI clock: DOCUMENTED https://www.resolume.com/index.php/support/en/midi-shortcuts -- "Resolume's BPM will follow along, as if you were tapping the beat by hand." No offset setting documented. "Tip! MIDI Clock was great in 1996. It's notoriously wavy and not really accurate." Third-party mention of a "clock offset" in other software: zerotovj (not Resolume): ignore.

### Q7 BPM section controls
Answer: Tap (sets tempo from your taps), Resync (hard-jumps everything on BPM sync to beat 1, bar 1, of the phrase, tempo unchanged), plus/minus (fine tempo change), Nudge Up / Nudge Down (temporary speed-up or slow-down while HELD, tempo restored on release), x2 and /2 (double / halve BPM), Pause. No control moves the beat a fixed small amount earlier or later without changing the tempo; the catch-up tool is Nudge (temporary tempo change) or Resync (hard cut).
- DOCUMENTED https://resolume.com/support/en/bpm -- "You do this by clicking the 'Tap' button a few times to set the tempo. ... After you've done this for a few beats, click the 'Resync' button on the first beat of the new phrase. When you press 'Resync', everything in Resolume that is set to BPM Sync will jump back to the first beat of the first bar of the first phrase."
- DOCUMENTED same page -- "You can fix it by increasing the BPM slightly by hitting the 'plus' button a few times. Of course, you can hit the 'minus' when it's arriving early, or just tap out a new tempo".
- DOCUMENTED same page -- "If you don't like the hard cut you get from pressing 'Resync', you can also press the 'Nudge Up' and 'Nudge Down' buttons. These will temporarily speed the tempo up or down while you have the button pressed, and set it back to where it was when you let go. This will let you catch up to the music, or let the music catch up to you."
- DOCUMENTED https://www.resolume.com/support/en/preferences -- "Tempo Nudge Range: When nudging the BPM up or down, this sets what percentage of the current BPM it shifts the BPM up or down with. 10% is good when doing actual audio stuff. Personally I think 25% is more suited when syncing visuals to music." (so Nudge size is a setting, a % of current BPM; default value: NOT DOCUMENTED.)
- DOCUMENTED https://resolume.com/support/en/link -- "when you hit x2 on the BPM to accentuate a musical climax" (x2 exists on the BPM bar); /2 is named in the forum https://resolume.com/forum/viewtopic.php?t=23012 ("x2, /2, resync functions" -- user). Exact behaviour of x2 / /2 on the beat phase: NOT DOCUMENTED. Older manual (Resolume 4 pdf, https://resolume.com/download/Resolume-4-Manual-English.pdf): "use the *2 and /2 buttons" -- that is the CLIP's beats count, a different control.
- Tap range: forum (Joris, staff, 2009 Avenue 3) https://resolume.com/forum/viewtopic.php?t=6090 -- tap button sits "right next to ... buttons that say 'Resync' and 'Pause'"; Tap default key Tab (that post: "mapped to the Tab key by default, I believe" -- Avenue 3, old). OSC thread (2009): BPM range 2 to 500: https://resolume.com/forum/viewtopic.php?start=20&t=4226 (THIRD-PARTY/old).
- Blue-square beat indicator (phase display): DOCUMENTED same BPM page -- "it should hit the top left corner on every first beat ... this square will light up with a little outline every 16 beats".
- What Resync does to the beat phase: DOCUMENTED = jump back to first beat of first bar of first phrase (hard cut, "everything ... set to BPM Sync"). Whether it re-aligns to the moment you press (beat 1 = now) vs. to a fixed grid: the sentence reads "jump back to the first beat" and the manual says press it "on the first beat of the new phrase", i.e. beat 1 starts NOW. That reading is INFERRED. Settle: with Tap running, press Resync mid-beat and watch the blue square snap to top-left immediately; and whether the tempo number is unchanged.
- "Also: Resync and Pause are disabled while Ableton Link is on" (see Q6).
- "Nudge" as a way to push picture a tiny bit earlier/later by a fixed time: NOT in any Resolume doc. Resolume's BPM Nudge is a temporary tempo change.

### Q8 What staff / users advise for picture + sound agreeing in a big room
Answer: Resolume's own pages offer no "FOH sync" recipe. What exists: (1) the per-screen Delay (to match physical outputs to each other, and, per staff, the knob to check when a screen is late); (2) SMPTE clip "delay compensation" with negative values for big stages; (3) Clip Start Offset for late-looking triggers; (4) users report an audio Master Output Delay in Preferences for the opposite direction (delay the SOUND to meet a late picture).
- DOCUMENTED https://resolume.com/support/en/smpte -- "Light travels faster than sound, so on very big stages the sound will take longer than the video to reach the majority of the crowd. A negative compensation can help with getting things perfectly lip sync again." (the only official sentence about big-room sound lag; SMPTE only.)
- STAFF Zoltan 2024-01-30 https://resolume.com/forum/viewtopic.php?t=23147 -- see Q1 (check a monitor on the output; if in time there, the delay is after the machine; else look at the Screen's delay).
- THIRD-PARTY 2017 https://resolume.com/forum/viewtopic.php?t=15098 -- user fixed late picture by delaying the sound: "Setting the Audio delay under preferences to 300ms, syncs the videos with audio."
- THIRD-PARTY (Oaktown) 2017 https://resolume.com/forum/viewtopic.php?t=14126 -- adjust each output "back to match" the most delayed one with the Delay.
- THIRD-PARTY (a 2011 user, author not captured) https://resolume.com/forum/viewtopic.php?t=7763 -- "video is far more latent than audio. there is no simple way round this. this is why you have delay settings for the audio" and a hardware delay unit on the PA feed. Old (Avenue 3 era).
- STAFF-adjacent (2013 thread, a reply from the Resolume side, author not captured) https://resolume.com/forum/viewtopic.php?t=10309 -- "You will probably find that the projector is adding the most delay, sometimes up to 5 frames." (projector latency of 5 frames ~ 83 ms at 60 fps).
- What a VJ standing mid-room needs (sound is LATE vs picture because sound travels ~343 m/s): this is the opposite of Resolume's Delay use case only in appearance: the Delay (picture later) is the right direction. (INFERRED arithmetic: 100 ms of sound = about 34 m of air path; so Resolume's 0-100 ms cap is enough for rooms up to about that depth.) No Resolume page says this.
- NOT DOCUMENTED: any Resolume staff post that says "use Screen Delay to line picture up with the sound at the mixing desk". Settle: ask on the Resolume forum or test with a clap-flash clip.
