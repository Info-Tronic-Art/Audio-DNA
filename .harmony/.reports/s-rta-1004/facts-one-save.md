## 3 WHAT A PLANNER MUST NOT ASSUME
1. That a show opens to its decks anywhere today, or that a row shows size / deck count / canvas: it shows a name and a date only (Q1). The Compositions section lists EVERY `*.json` in the folder, the Decks section lists any file with a top-level "layers" (a SHOW file passes).
2. That Load Deck refuses a show file: it does not (shape check = "layers" only). Result is an empty deck plus possibly new live layers with the file's layer settings, and a following Save Deck overwrites the show file with deck JSON (Q2, INFERRED chain).
3. That a deck file and a show file differ at the top level: both have "layers"; in a deck it means ROWS (`{clips}`), in a show it means shared-layer SETTINGS. A show has no "id" and no "numColumns" (Q2, Q3).
4. That the show has a version: there is none; the only shape test is "layers" present (`ShowMigration::isLegacyShow`). Boris's own saved show is in the OLD shape and loads only through the migration (his disk).
5. That the "looks" and FX Save are clip, layer or deck effects: they are a snapshot of the legacy global chain + legacy mappings, the editor for that chain is hidden, and the show does not hold them (Q6; Pitfall 28 names the same split for Eyes). A removal also leaves `EffectsRackPanel::refreshFromChain` and the legacy chain in place.
6. That FX Save slots can be recalled by key, MIDI, OSC or REST: only the mouse on the slot number button can; `loadSlotPreset` has no caller (Q6).
7. That key/MIDI bindings can be momentary, relative, Selected, ThisItem or velocity-scaled from the UI: no code sets those fields; only an imported file can (Q4; CLAUDE.md lists them as capabilities). `Import Bindings` of a JSON without a "bindings" array erases all bindings and says nothing.
8. That a binding names a device: it names a key / note / CC and a channel only; the app opens every MIDI input found at launch, with no picker and no hot-plug (Q4).
9. That `targetClipId` survives a show reload: clip ids are re-minted at every load (Pitfall 36, `remintClipIds`).
10. That `fromVar` of bindings is a merge: it clears the list, re-mints ids, clears relative-CC state, ignores `bindingMode_`, and an absent "enabled" key loads as disabled (Q4).
11. That window layout is the window: it is two numbers (an ABSOLUTE pixel y and three fractions); window size / position, tabs and outputs are not in it; fractions are not clamped on load (Q5).
12. That the composition-level `autopilot*`, `crossfader*`, `genre*`, `smartAutopilotEnabled`, `outputDisplay`, `bpmMultiplier` keys do anything: saved and loaded, read by no consumer (Q3). Do not carry or "restore" them as if live.
