### Q1 Create / destroy, the object per output, every field, "the same screen"

ANSWER. One `output::OutputManager` (owned by MainComponent as `outputs_`, message thread only) keeps `std::vector<Live> live_`. One `Live` = `{ std::unique_ptr<OutputWindow> window; DisplayInfo target; }`. That is ALL the per-output state the manager holds; there is no per-output setting of any kind. An output is a borderless `juce::DocumentWindow` (`OutputWindow`) covering one display, with its own `juce::OpenGLContext`. "The same screen" is recognised ONLY by a fingerprint of six values: `DisplayInfo{x, y, w, h, scale, isMain}` taken from JUCE `Displays::Display::totalArea` (logical points), `scale`, `isMain`. No display id, no name, no UUID.

Creation (VERIFIED):
- Doors: `toggleDisplay(i)` -> `openDisplay(i)` -> `openWindow(i)` (src/output/OutputManager.cpp:62-103). `openWindow` builds `Display` -> `DisplayInfo target`, refuses if a live output already has an equal target (:78-80), `make_unique<OutputWindow>(frames_)` (:82), wires `onCloseRequested` and `onDisplaysChanged` (:84-85), calls `window->openOnDisplay(display)` (:86), pushes `{window, target}` (:87). Then `openDisplay` does `forgetInterrupted`, `forgetSaved`, `changed()`, `persistWanted()` (:99-102).
- `OutputWindow::openOnDisplay` (src/ui/OutputWindow.cpp:112-135): `setBounds(display.totalArea)`, `setVisible(true)`, `toFront(false)`, set the child component to the local bounds. Bounds before visible.
- Other openers: `restoreLast()` (:328-352, only caller `MainComponent::handleMenuCommand` case `kOutputRestoreLast`, src/MainComponent.cpp:7221) and the hot-plug reopen inside `reconcile()` step 2 (:248-255).

Destruction (VERIFIED): `closeDisplay` / `closeAll` / `closeWindow` -> `closeLive(i)`: moves the window out of `live_`, `setVisible(false)`, `destroyLater` (graveyard_ + `triggerAsyncUpdate`); the graveyard is cleared in `handleAsyncUpdate` (:152-188). The destructor `~OutputWindow` calls `detachGL()`. `shutdown()` (:430-446) detaches GL of every window, clears live_ and graveyard_, `setLiveOutputCount(0)`; it writes no settings. A hot-plug close (`reconcile` step 3, :257-267) pushes the target to `interrupted_` and calls `closeLive`.

EVERY field of state:
- `OutputWindow` (src/ui/OutputWindow.h:46-75): `OutputComponent outputComponent_` (paints black); `juce::OpenGLContext glContext_`; `Presenter presenter_` (holds `SharedFrameSet&`, `OpenGLContext&`, `output::PresenterGLState state_`); public `std::function<void()> onCloseRequested`, `onDisplaysChanged`. `PresenterGLState` (src/output/OutputPresenter.h:15-24): `tex[4]`, `readFBO[4]`, `held[4]` (IOSurfaceRef, CFRetain'd), `boundGen`, `w`, `h`. The window has no title, no setting, no delay, no device.
- `OutputManager` members (src/output/OutputManager.h:120-138): `frames_&`, `renderer_&`, `live_`, `graveyard_`, `shutDown_`, `lastSeen_` (display list at last reconcile), `interrupted_` (targets closed by hot-plug), `saved_` (set loaded from settings.json, opened only by restoreLast), `lastWanted_`, `settingsFile_`, `reconcilePending_`, atomics `pollEnabled_`, `pollTicks_`, `reconciles_`, `settingsWrites_`, `restoreCalls_`, `interruptedCount_`, `savedCount_`, `restorable_`, `std::mutex stateMutex_` + `juce::var stateSnapshot_` (for HTTP readers).
- All of `interrupted_`, `saved_`, `lastSeen_`, `lastWanted_` are `std::vector<DisplayInfo>` -- the fingerprint, nothing else.

"The same screen" across launches and hot-plug (VERIFIED, src/output/OutputTargets.h:15-37, OutputTargets.cpp:5-105):
- `DisplayInfo` comment: "JUCE's Display has no id and no name, so a display is recognised by this fingerprint" (OutputTargets.h:15-16). I also checked JUCE 8.0.4's `Displays::Display` struct (build/_deps/juce-src/modules/juce_gui_basics/desktop/juce_Displays.h:~50-110): fields are isMain, totalArea, userArea, safeAreaInsets, keyboardInsets, topLeftPhysical, scale, dpi, verticalFrequencyHz. No id, no name (VERIFIED).
- Equality = all six fields equal (OutputTargets.h:24-27). `isLive(i)` and `closeDisplay(i)` match `live_[].target == displays[i]` by that equality (OutputManager.cpp:35-51, 112-121).
- Ladder (`matchDisplay`, rungs in OutputTargets.cpp:21-26): Reopen (a target with no window, or a saved one) = Exact -> SameSize (w,h,scale equal, any position) -> Main (saved.isMain && current.isMain). Track (a LIVE output following its display) = Exact -> SameSize -> SameOrigin (same x,y, other w/h/scale = a mode change) -> Main. Loose rungs only consider displays that are new or changed since the previous display list (`diffOutputs`, :57-105), so an output never jumps onto an untouched display. With two identical displays, position wins, then the first unused one (OutputTargets.h:39-40).
- Across launches: the saved set is the fingerprint list in settings.json; "Restore Last Outputs" runs the Reopen ladder (`restorePlan`, OutputManager.cpp:307-321).
- Consequence (VERIFIED by reading, not run): a display that is re-arranged (new x,y) or changes resolution/scale is the "same" screen only by the loose rungs; two identical monitors are told apart only by position, then by order in `Desktop::getDisplays()`.

### Q4 THE RENDER PATH

ANSWER. The canvas is rendered once per frame by the main `Renderer` on JUCE's single shared OpenGL thread into `canvasFBO_` (RGBA8). When any output is live the same thread copies the finished canvas into a 4-slot ring of IOSurfaces (BGRA, 4 bytes/pixel); each output window has its OWN GL context that blits the newest completed slot into its window framebuffer, letterboxed, once per refresh of ITS display (display-link triggered). No GL object is shared between contexts; the IOSurfaces are the only shared thing.

Format and size (VERIFIED): canvas texture `GL_RGBA8`, `GL_UNSIGNED_BYTE`, size = `RenderGeometry::resolveCanvas(test lock, Composition::outputWidth/outputHeight)` with default 1920x1080 (Renderer.cpp:906-929; RenderGeometry.h:12-23; Composition.h:194-195). Bytes per frame (arithmetic, 4 B/pixel):
- default canvas 1920x1080: 8,294,400 B = 7.91 MiB per frame (one canvas texture; ring of 4 slots = 33,177,600 B = 31.6 MiB).
- 3840x2160: 33,177,600 B = 31.6 MiB per frame (4 slots = 132,710,400 B = 126.6 MiB).
- plan5-final.md 8.6 states the same budget: "4 x canvas RGBA (32 MiB at 1080p ... 127 MiB at 4K)" (VERIFIED as text; the arithmetic is mine and agrees).
Each output has no frame storage of its own: 4 texture objects bound to the shared surfaces plus 4 read FBOs (PresenterGLState) plus the OS window framebuffer.

Numbered path, "canvas rendered" to "pixels on output N" (VERIFIED unless marked):
1. `Renderer::renderOpenGL` (JUCE "OpenGL Renderer" thread, shared by every JUCE GL context: juce_OpenGLContext.cpp:966 `SharedResourcePointer<RenderThread>`, :746-890). Resolves canvas size, `ensureCanvasFBO` (Renderer.cpp:464), binds `canvasFBO_`, clears black (:468-472).
2. Compositor / effect passes write the canvas (:684-773); `applyCompTransform` (:773); master-opacity pass as the last writer (:795-815).
3. `publishToOutputs(canvas.w, canvas.h)` (Renderer.cpp:819; defined :966-972). Returns at once unless `liveOutputs_ > 0` or the TEST-ONLY `outputTapForced_`. Also called on the three early paths: fenced-hold (:426), nothing-to-render (:484), no-content (:746).
4. `SharedFrameSet::publish` (src/output/SharedFrameSet.cpp:16-76): `pool_.ensure(w,h)` (a size change creates a NEW generation of 4 IOSurfaces and retires the old one for 120 publishes); `pool_.tick()`; rebinds this context's rect textures and 4 FBOs on a generation change.
5. If the previous copy's fence is complete (`glClientWaitSync` timeout 0, non-blocking), that previous slot is published as the new FRONT: `front_.store(packFront(gen, ++serial_, slot), release)` (:46-62). If the fence is NOT complete the whole call returns: no new copy, front unchanged ("GPU behind: skip this frame, never two copies in flight", :49-50).
6. Otherwise `write_ = (write_+1) % 4` (strict round robin), `glBlitFramebuffer(canvasFBO -> fbo_[write_])` 1:1 GL_NEAREST, `glFenceSync`, `glFlush`, rebinds the canvas FBO (:64-72). So front lags the newest rendered canvas by one publish: "+1 frame of latency" (SharedFrameSet.h:117-119; docs/claude/rendering.md:160).
7. Back in the Renderer: `presentCanvas` (the preview panel, :822), recorder, Syphon, capture (see Q5).
8. Output side: each `OutputWindow` has `glContext_` with `setContinuousRepainting(true)`, `setSwapInterval(0)` set in `Presenter::newOpenGLContextCreated` (OutputWindow.cpp:10-16, 69). On macOS JUCE registers each continuously-repainting context with `PerScreenDisplayLinks`; a link tick for the context's display calls `triggerRepaint()` (juce_OpenGLContext.cpp:895-912).
9. The single render thread's `renderAll()` iterates every registered context, running a context's `renderOpenGL` only if that context has `pendingRender` (juce_OpenGLContext.cpp:360-362, 746-830), sequentially, on the SAME thread as the main renderer.
10. `Presenter::renderOpenGL` (OutputWindow.cpp:18-27) reads the window framebuffer id and physical size (component size x rendering scale) and calls `output::presentSharedFrame` (src/output/OutputPresenter.cpp:78-108): clear black; `frames.front()` (one acquire load); rebind this context to the front generation if it changed (CFRetain of the 4 surfaces; `CGLTexImageIOSurface2D`); re-bind `readFBO[f.slot]` EVERY frame; `glBlitFramebuffer(slot -> window FBO, GL_LINEAR)` into `RenderGeometry::fitCanvas(canvasW, canvasH, targetW, targetH)` (letter/pillar box, centred).
11. JUCE swaps the output context's buffers (swap interval 0) and the window server shows the window (a normal-level borderless window covering the display).
Pacing: the main context keeps JUCE's default swap interval 1 (Renderer never sets it: grep for setSwapInterval finds only OutputWindow.cpp:15; juce_OpenGLContext.cpp:660 sets 1). plan5-final.md 8.6 says the shared render thread blocks in the main context's swap and an output whose link fires meanwhile renders right after it, "worst case one projector refresh of extra latency (INFERRED)" -- labelled INFERRED there too; not measured.
macOS only: elsewhere `publish` is a no-op and `presentSharedFrame` leaves the target black (VERIFIED #else branches).

### Q6 Frame-history machinery

ANSWER. Several frame-history stores exist, none is an output-delay store, and NOTHING today shows an output a frame other than the newest completed one.

Inventory (VERIFIED unless marked):
- `SharedFrameSet` / `SurfacePool` (src/output/SharedFrameSet.h): 4 BGRA IOSurface slots of full canvas size (`kSlots = 4`, :65), strict round-robin writer, generation retired after `kRetireFrames = 120` publishes. Header says grace between "no longer front" and "rewritten" = `kSlots - 2` = 2 main frames (:64). Only `front_` (gen, serial, slot) is published; readers present `front().slot` (OutputPresenter.cpp:97). So the older slots physically hold the previous 2-3 canvas frames, but there is no index API, no guarantee beyond the 2-frame grace, and the writer rewrites them. This is a pipeline, not a history.
- `CompositorEngine::FrameRingBuffer` (the FrameRingBuffer of Pitfalls 19/20; src/render/CompositorEngine.h:333-363): per clip chain (key = `LayerStateKey` with `kShowStackKey`, Pitfall 35) up to `kMaxRingFrames = 480` cells, each a downscaled RGBA8 texture + FBO: stored width = canvas / `RenderGeometry::ringDownscale(canvasW)` (`(w+479)/480`, min 4, RenderGeometry.h:~45-50) -> 480x270 cells at 1080p and at 4K. 480 x 480 x 270 x 4 = 248,832,000 B = 237.3 MiB per full ring (arithmetic; matches Pitfall 20 "237 MiB per full ring at 1080p and 4K"). Cells created on first write, at most one per ring per frame (`pushFrameToRing`, CompositorEngine.cpp:1761-1790); index math in src/render/FrameRing.h. Used by Screen Split / Frame Stutter effects only, inside the clip/layer chain BEFORE the canvas is final. Not readable by an output.
- `TemporalBuffer` (CompositorEngine.h:316-322): one full-size prev-frame FBO per chain (`u_prev_frame` for Echo / Freeze / Posterize Time / Frame Delay). One frame deep, pre-canvas.
- `FeedbackProcessor` per-layer ping-pongs (CompositorEngine.h:~308); pre-canvas.
- `VideoRing` of `VideoPlayer` (src/media/VideoPlayer.h:181-188): `kSlots = 3` decoded video frames per player, with a decode-thread GOP cache (budget `min(2 GiB, RAM/16)`, src/media/GopCache.h:16-35) -- source-media history, Pitfalls 56 / 60 / 62.
- `ImageSequence` slot table under `SeqVram::kBudgetBytes = 1 GiB` (src/media/SeqVram.h:30; Pitfall 54) -- source-media textures.
- `VideoRecorder` 3 CPU readback buffers (Q5) -- a transport to the encoder, not readable by anything else.
Budget rules, as the code/docs state them: ring cell width never over 480 px and created lazily (Pitfall 20); SharedFrameSet = 4 canvas-size surfaces once, shared by all outputs (plan5-final.md 8.6); sequences 1 GiB; video GOP cache 2 GiB max; video upload budget per frame (Pitfall 60).
Is anything showing an OUTPUT an older frame? VERIFIED NO: `presentSharedFrame` reads `frames.front()` only (OutputPresenter.cpp:87-99); no per-output frame selector, no delay parameter, exists in `OutputWindow`, `OutputManager`, `Presenter` or `PresenterGLState`. An output can show the SAME frame repeatedly (display faster than the main render) or hold the last frame while the preview GL context is down (VERIFIED by design comment, SharedFrameSet.h:7-11, and test `writer_context_loss_keeps_last_frame`).

## 3 WHAT A PLANNER MUST NOT ASSUME
---------------------------------------------------------------------------------------------------
1. There is NO properties window, NO per-output setting, NO "Device" notion and NO delay anywhere today (Q2). "Output display properties" is a new surface; the nearest existing thing is the Output menu / TopBar list of "Display N (WxH)" ticks.
2. "Device" has no meaning in the current code: an output is a window on a JUCE `Displays::Display`; JUCE exposes NO display id or name (VERIFIED in JUCE 8.0.4 juce_Displays.h). The only identity is the (x, y, w, h, scale, isMain) fingerprint. A setting keyed to "this screen" inherits the fingerprint's weaknesses: it changes when the arrangement moves, the mode changes, or the main flag flips (the loose rungs rescue only some cases). Whether a native display id (e.g. CGDirectDisplayID) is reachable from the window was NOT checked.
3. The ring of 4 IOSurface slots is a pipeline, not a history. Do not read "4 slots" as "3 frames of delay available": presenters read only `front().slot`; the writer rewrites a non-front slot after a 2-frame grace (SharedFrameSet.h:64) and may skip a publish entirely when the GPU is behind (SharedFrameSet.cpp:49-50). A frame older than the newest completed one is not addressable (VERIFIED, Q6).
4. `FrameRingBuffer` (480 cells, 237 MiB) is per clip chain, downscaled to <= 480 px wide and sits BEFORE the canvas (Screen Split / Frame Stutter). It does not hold canvas frames and an output cannot read it (Pitfalls 19, 20, 35).
5. All output contexts and the main renderer share ONE GL thread (juce_OpenGLContext.cpp:966 `SharedResourcePointer<RenderThread>`). An output's `renderOpenGL` must never block (Pitfall 40: swap interval 0, set in `newOpenGLContextCreated` because JUCE forces 1 just before it). Adding work or waits per output costs the main frame.
6. The tap is zero-cost only while no output is live (`publishToOutputs` early return, Renderer.cpp:968). Any delay buffer that must be filled continuously would change that cost model (that is a fact about today's gating, not advice).
7. Outputs are machine state, never file state (plan5 R7; integration.md:27): do not put output data in a deck/composition file; `outputDisplay` is dead (default -1, deck file writes 1 and ignores it) and test_output_law forbids naming it in OutputManager/MainComponent.
8. The app NEVER opens an output by itself (plan5 Q1): `restoreLast()` has exactly one call site and test_output_law pins it; the constructor and `attachSettings` must contain no opener. A new "restore delay at launch" path must not open windows.
9. Settings writes are change-gated and replace the `outputs` key whole; `persistWanted` is asserted by test_output_law to call `wantedSet(` with `saved_)`. A new per-target field added only to `DisplayInfo` is part of `operator==` (OutputTargets.h:24-27), i.e. it would silently become part of the "same screen" identity unless kept out of equality (consequence of the code as written; INFERRED for any new field).
10. `wantedFromVar` skips entries without positive w/h/scale and ignores unknown keys and `version`: an old build reading a file written by a newer one drops nothing but also never sees new keys (VERIFIED by reading; not run).
11. Docs disagree with code in small ways: (a) integration.md says the test-mode scratch settings file is `~/Library/Caches/Audio-DNA/test-mode-settings.json`; the code uses `tempDirectory.getNonexistentChildFile("test-mode-settings", ".json")` (AppSettings.cpp:14-15) and the test only asserts "a child of the temp directory"; the exact macOS path was not checked. (b) AppSettings.h says "~/Library/Audio-DNA/settings.json on macOS" -- INFERRED consistent. (c) `tests/visual/test_output_window_level.py` docstring cites a defect line that no longer exists. (d) The enum still holds dead `kOutputIdentifyDisplays` / `kOutputTestCard`.
12. Binding rules in CLAUDE.md / pitfalls that bind this area: Pitfall 37 (canvas is the composition; every consumer reads exactly canvas size; never size anything from a Component), Pitfall 40 (normal level, never key, read only the shared IOSurface frames, never a GL name of the main context, fences die with their context so `releaseGL` drops without `glDeleteSync`), Pitfall 57 (a timer-driven `repaint()` costs the whole window: relevant if a properties panel animates), Pitfall 60 (an IOSurface slot returns only after its fence), Pitfall 52 (one capture at a time), Pitfall 5 (any new slider must be `ResettableSlider` with `setDefaultValue`), CLAUDE.md "PopupMenu: showMenuAsync with parent top-level component", CLAUDE.md "Outputs" rule (one item list; an output window never takes the keyboard; Cmd+Shift+Esc = all off; the app never opens an output by itself), and the Sacred Rules (no mutex on hot paths, UI -> hot path via `Relaxed<T>` / atomics, Pitfall 63).
13. No automated gate may open an Output window (SCREEN-SAFETY LAW; HANDOFF.md:105-135). Anything about delay timing that needs a real window can only be measured under Boris's supervision or offscreen via the existing private-context probe.
14. The Presenter measures its target in physical pixels (`getRenderingScale`) and blits with `GL_LINEAR`; an output on a display of a different size/scale than the canvas is a scaled blit, not a 1:1 copy (VERIFIED OutputPresenter.cpp:96-99).
