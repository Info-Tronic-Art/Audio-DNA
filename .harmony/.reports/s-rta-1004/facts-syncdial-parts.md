### Q2 What the dial is, as built
Answer (VERIFIED unless marked):
- "LATER" (D > 0) delays AUDIO SAMPLES, not features, not the beat clock, not frames. `AnalysisDelayLine` (src/analysis/AnalysisDelayLine.h, 64 hops x 512 floats at 48 kHz, 128 KiB allocated once in the AnalysisThread constructor) sits between `AnalysisResampler::pullHop` and the 2048-sample analysis window (AnalysisThread.cpp serviceOnce, lines 107-160 at 740b6d6). Each hop is stamped with the pass's clock when drained; `processHop` (the 14 stages + publish) runs only when now >= stamp + applied D (`frontDue`), or when the line is full (counted as `lineOverruns`, expected 0). So the whole analysis (loudness, onsets, spectrum, BPM tracker, beat clock, PCM readout) runs D ms late and every FeatureBus reader (render, REST, recorder) sees audio from D ms ago. The delivered-sample counter, AudioTap and the file transport stay live (Pitfall 68, lane text, not merged).
- The applied D glides toward the target at 0.25 ms per ms (`SyncSlew`, first value snaps); range -500..+500 ms, whole ms (`SyncOffset::clampMs`). The snapshot carries `syncOffsetMs` (FeatureSnapshot.h offset 332, provenance, sizeof stays 384).
- "EARLIER" (D < 0) delays nothing and moves nothing else: `BeatLead::apply` (src/analysis/BeatLead.h/.cpp, 234 lines of cpp) runs after stage 14 and rewrites ONLY nine beat fields of the snapshot (beatPhase, totalBeatCount, beatInBar, downbeatDetected, barPhase, barCount, totalBarCount, resyncBarOrigin, phrasePhase) to the tracker's own predicted-beat rule run |D| ms ahead (bpm x lead / 60 beats). Onsets, loudness and the rest stay on time. It holds the fields while the tracker moves its own beat position back, re-bases (with "excess" counters beatX / barX) at deliberate frame moves, and slews the lead at <= 0.25 beat per beat. To get those moments it adds read-only views and a `frameEpoch_` counter to BPMTracker (+1 at Resync, Tap realign, downbeat lock / relock, phrase reset, lock lost).
- Room list: `SyncVenues` (src/sync/SyncVenues.h): venues = {name, ms}, at least 1, at most 64, names 1..40 chars unique case-insensitively, `current` names one; ops select / create (copies the current offset) / rename / remove / setMs / nudge. Stored in the machine's settings.json under `AppSettings::kSync = "sync"` as {"version":1,"current":"Default","venues":[{"name","ms"}]} - NOT in a composition. `SyncOffsetController` (src/sync/, message thread) applies every op, pushes the target atom to the analysis thread, keeps a lock-free status copy (`WitnessRing`), debounces the save 500 ms (`kSaveDelayMs`), flushes at destruction. TEST-SERVER env `AUDIODNA_SYNC_TEST` turns persistence off.
- REST (ApiServer.cpp, 740b6d6 / 9eab9bd): `GET /api/sync`; `POST /api/sync/set`, `/nudge`, `/venue` (select or create), `/venue/rename`, `/venue/remove`. TEST-SERVER only: `GET /api/debug/sync_witness`, `POST /api/debug/sync_persist`; on KEYS also `POST /api/debug/binding_action`, `POST` and `GET /api/debug/midi_learn`. OSC: `/audiodna/sync <ms>` and `/audiodna/sync/nudge <ms>` (OscHandler.cpp).
- Sync binding targets: `Binding::Action::SyncNudge` appended (22nd action) with `targetSyncStepMs` (+1 / -1). Painted targets "Sync -1 ms" and "Sync +1 ms" in the global row of the bind overlay and the MIDI-learn overlay (MainComponent::buildBindableTargets). A key or note press nudges by the step; a Relative CC by ticks x |step|; an Absolute CC is ignored. KEYS adds `bindingIsLive`: MIDI learn refuses a CC on a Sync target (so no screen can make a live CC binding; a hand-made bindings file's Absolute entry loads inert).
- Take recorder: `RecorderHost::tick` (src/recording/RecorderHost.cpp, commit 9bd1efe + ef0d8e6) stamps every take point in "show time" = delivered samples minus the LATE offset's samples (`snap.syncOffsetMs`); a with-audio replay fires a point stamped s when the transport reaches s + D; EARLY subtracts nothing; the replay end fires leftover points in stamp order. The offset itself is never recorded into a take or routine and is not a ControlPath (SyncOffsetController.h header comment). At D = 0 all of this is arithmetic on 0.
- On-screen control: NONE in either branch. No TopBar / SYNC button / panel / wheel change exists (git diff stat: src/ui touches only BindingOverlay, MidiLearnOverlay). Those were stages S5a / S5b, never started.
Evidence labels: all VERIFIED (read in the files named). "no consumer extrapolates from snapshot time" rule lint: tests/test_snapshot_time_lint.cpp (textual, declared debt in its header).
