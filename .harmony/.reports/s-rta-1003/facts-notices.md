## 1. The rule and the classes

Boris, verbatim, 2026-10-03 15:30:49 (`.harmony/boris-feedback-backlog.md` "Boris on notices", BF32; `.harmony/binding-decisions.md` "No what happened texts"):

> "We don't need any text indicating what has happened or what has happened. That is something that happens online and is not necessary in this application. It is extra overhead and bloat. Please remove it cleanly and completely."

Boris, verbatim, 2026-10-03 15:42:01, asked whether texts that were in the app before today go too (failure reports kept until he saw a list):

> "remove the list entirely and cleanly"

Classes used below:
- A = event notice: text on screen because something happened (note, banner, label message, report-only OK alert, progress text, undo hint).
- B = failure report: same, but it reports a refusal, error or fault (yellow/red warning line, error label text, failure alert).
- C = state display (a value or indicator of the current state). Kept.
- D = decision dialog (he must choose). Kept.
- E = tooltip, menu item, static caption, help, empty-state text, non-text feedback. Kept.

Counts: A 23, B 21, C 9, D 6, E 11 (rows, not call sites; one row can cover several call sites).

Two design facts that decide the shape of the removal (VERIFIED):
1. `fileLabel_` (MainComponent.h:343, `setFileLabel` MainComponent.cpp:3182) is ONE widget that carries both state (C: current file / source / mic name) and events (A/B). The widget must stay; only the event WRITES go. Eyes reads it (`/api/debug/ui_text`, MainComponent.cpp:2164).
2. The Record tab has ONE shared notice widget (`noticeLabel_`) fed by two `dispatch.notify` lambdas (MainComponent.cpp:2049-2058 and :2081-2085) plus the string a Record-tab button's funnel returns (`RecordPanel::runAction`, RecordPanel.cpp:217-228). Each lambda also writes `std::cerr` (the log twin). The funnels (`perfRecord`, `perfStop`, `perfRoutineSave`, ...) also RETURN the same strings to REST / OSC / bindings; those return values are not screen text and the removal must not change them.
