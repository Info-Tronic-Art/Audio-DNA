## Problems (all verified at HEAD)

One reader relinquishes a buffer another still reads; the writer reclaims and overwrites mid-read. NOT fixable by memory order (08f7361 fixed the single-reader/single-writer fences only).
- **P1 consequence (traced honestly):** no crash/OOB — consumers are switch-default/bounds-checked (AudioReadoutPanel.cpp:464/477-484/…), arm64 aligned scalars don't tear. Real damage = mixed-generation snapshots producing SPURIOUS EDGES against persistent state: structuralState transitions drive playlist advance (Renderer.cpp:352/363/373), genre-change callback (Renderer.cpp:255-258), beatInBar==0 autopilot triggers (Autopilot.cpp:56) — "the rig changed scene by itself," the worst live-VJ failure class, undebuggable mid-set.
- **P2 — multi-writer race, real-now:** POST /api/inject_features (ApiServer.cpp:607-648) does acquireWrite/publishWrite on the HTTP thread while AnalysisThread runs in default production (MainComponent.cpp:1568-1615, ApiServer started unconditionally). Both writers get the SAME staging pointer (FeatureBus.cpp:12-17) → interleaved struct assignment with attacker-chosen values. Bound to 0.0.0.0:7070, unauthenticated (ApiServer.cpp:54).

## Council record (condensed; full papers in session transcript)
- **MINIMAL:** mutex + 320B value copy; delete acquireRead/kNewFlag (verified: no reader consumes new-vs-stale; every site is a null-fallback triad). GL path already takes ~20 mutexes/frame (activeSourceMutex_ Renderer.cpp:185 etc.) so lock-purity is already dead. P2: delete the production writer (registration gate) — production injection is dead-by-design (overwritten ≤10.67ms; tests/README.md:25) and a writer mutex can't fix the incremental-fill splice (AnalysisThread.cpp:97→303). Anti-seqlock: naive payload copy = permanent TSan suppression.
- **CORRECT:** seqlock with `std::array<std::atomic<uint32_t>,80>` payload — defined behavior, ZERO TSan suppressions (neutralizes minimal's anti-seqlock argument; `std::atomic_ref` verified UNAVAILABLE on this toolchain). Move-only `FeatureBus::Writer` handle = second writer is a compile error; readers hold `const FeatureBus&` = future mutation stops compiling. Writer-private staging closes the slot-held-open-across-200-line-fill window. Measured: sizeof(FeatureSnapshot)=320, trivially copyable; publish 10.67ms cadence; ~30ns copy; retry fail ~1e-20 with last-good fallback. Anti-mutex: priority inversion vs Priority::high analysis thread + modal-file-picker message thread (MainComponent.cpp:1569, 2793-2812).
- **PRAG:** ship order matters: two one-line guards TODAY (loopback bind + test-mode gate) retire P2 + the venue attack surface with zero concurrency work; seqlock SECOND on its own schedule with a real test gate. Hit-rate math: P1 conjunction lands many times/sec (steady-state, not rare). Test truth: the only concurrency test has ONE reader (test_feature_bus.cpp:151) — structurally blind to P1; any fix must land with a multi-reader case shown failing first. Bonus: handleLoadImage arbitrary-file load is a venue hazard closed by loopback.

## Chair adjudication (mechanism-by-mechanism, with reasons)
1. **Read mechanism → SEQLOCK with atomic-word payload** (correct+prag over minimal). The only argument against seqlock (TSan blinding) is eliminated by the atomic-array construction; the mutex's priority-inversion exposure on a Priority::high writer vs a modal-capable message thread is a live-show stall class we shouldn't buy when the alternative is bounded-retry + last-good-fallback at ~1e-5 writer duty. Minimal's own fallback ("try_lock + stale copy") converges toward seqlock semantics anyway. Lock-free-on-GL is preserved as a DESIGN PROPERTY, not abandoned because it's already violated elsewhere.
2. **Pointer handout → DEAD** (unanimous). Value copies only; per-reader freshness via caller-held seq counter; kNewFlag machinery deleted (unanimously evidenced as unused + broken-at-N-readers).
3. **P2 → GATE, don't arbitrate** (minimal+prag over correct's relay). Production injection has zero users and is dead-by-design; building a relay to protect a 10ms-lifetime value is machinery for nothing. Correct's callback-relay design is RECORDED below as the upgrade path if a production injection need ever materializes.
4. **Binding → loopback default + env escape hatch** (prag adopted; chair decision on a reversible technical default). Zero non-localhost clients exist in-repo; the escape hatch (`AUDIODNA_API_BIND=0.0.0.0`) preserves remote-control workflows per-launch. Boris holds the veto + the "do you want remote control at all" workflow question (his list; if yes long-term → token auth follow-up).
5. **Staging → prag's order** — Step 1 today (tiny, reversible, no semantics change), Step 2 next-session-start (long-task deferral: a 12-file concurrency-core rewrite must not squeeze against a 40% EOS cap; it gets a fresh session with fix-round headroom), Step 3 after Step 2 survives real use.

## Chosen design — requirements
- **R1** Readers receive caller-owned VALUE copies; no pointer to shared storage escapes FeatureBus. API: `FeatureSnapshot read() const` + `bool readIfNewer(FeatureSnapshot&, uint64_t& lastSeq) const` (per-reader freshness).
- **R2** Seqlock: `alignas(64) std::atomic<uint64_t> seq_` (odd=publishing) + `std::array<std::atomic<uint32_t>, 80> words_`; memcpy via local; bounded retry (4 attempts) → last-good fallback; ZERO TSan suppressions tolerated (atomic_ref unavailable on toolchain — verified).
- **R3** Writer-private `staging_`: `acquireWrite()` returns `&staging_` (the ~200-line fill body at AnalysisThread.cpp:97→303 is untouched); `publishWrite()` = seq→odd, store words, seq→even. Closes the fill-window exposure.
- **R4** Single writer enforced at COMPILE time: move-only `FeatureBus::Writer`; the claim site is the existing testMode_ branch (MainComponent.cpp:1568) — production→AnalysisThread, test→TestServer.
- **R5** All reader sites go one-line mechanical (`FeatureSnapshot snap = bus.read();`); readers hold `const FeatureBus&`; DELETE acquireRead/getLatestRead/hasNewData/kNewFlag.
- **R6** inject_features: production = not registered (ctor flag from testMode_) → 404/403; enum inputs clamped (ApiServer.cpp:628/631/633); TestServer test-mode path unchanged. [Step 1]
- **R7** Snapshot parking: `CompositorEngine::latestSnapshot_` (CompositorEngine.h:133) + `EffectChain::latestSnapshot_` (EffectChain.h:92) must reference PERSISTENT per-renderer member storage refreshed each frame (or become values). Explicitly closes the existing dangling-stack bug: `defaultSnap` stack locals (Renderer.cpp:216, OutputWindow.cpp:107) escape into those fields, outlive render(), and EffectChain is SHARED with the second GL thread. [Step 2; cross-feeds OutputWindow lane]
- **R8** API bind default 127.0.0.1; `AUDIODNA_API_BIND` env opt-in restores 0.0.0.0. [Step 1]
- **R9** Test gate for Step 2: multi-reader TSan case (1 writer + 2 GL-cadence + 3 timer-cadence readers), tearing assertion (writer stamps rms==peak==float(i), timestamp==i; readers assert coherence + non-decreasing timestamps), DEMONSTRATED racing under TSan against the old protocol before the change and clean after; `createWriter()` double-claim failure test; zero suppressions; forced rebuild before every ctest claim.
