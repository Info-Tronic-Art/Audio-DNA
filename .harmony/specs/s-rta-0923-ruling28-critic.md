# Critic on s-rta-0923-ruling28-audio-store.md (independent, fable)

**Scope read:** the full spec, the sibling plan, every file under `src/recording/` it touches, both test files, both CMake files, `CombinedCallback.h`, rulings 25-28, HANDOFF s168→end, the review report, s167 D1/D10/D11/D12, and the JUCE sources behind each of the spec's VERIFIED claims. Read-only; nothing written.

## Findings

**1. BLOCKING — The crash-recovery premise (D-A3, §7.1) is false in the shipped configuration.** The spec says a crashed recording's WAV "is readable up to the last flush" because `ThreadedWriter` flushes periodically. VERIFIED otherwise: the flush is gated on `samplesPerFlush > 0` (`juce_AudioFormatWriter.cpp:304`), the default is `0` (`:341`), and `AudioTap` never calls `setFlushInterval` (grep of `src/recording/AudioTap.cpp` — only `ThreadedWriter` construction at `:126-127`). The WAV header is written once in the writer ctor with `lengthInSamples = 0` and again only in its destructor (`juce_WavAudioFormat.cpp:1623,1628`); the reader takes `lengthInSamples` from the header's data-chunk length with no file-size fallback (`:1348-1352`). So a crash mid-show leaves a multi-GB file that reads as **0 frames**, and the spec's "finalize() later is the whole repair" writes a sidecar with `frames: 0` and a header-only `fp1`. Fix: `threadedWriter_->setFlushInterval(static_cast<int>(rate_ * 10.0));` right after `AudioTap.cpp:127` (runs on the `TimeSliceThread`, not the audio thread — `flush()` seeks back, rewrites the header, seeks forward, `:1667-1679`), state the bounded loss (≤ flush interval), and put `AudioTap.cpp` under Lane A or B ownership — every lane currently forbids it (§10).

**2. BLOCKING — The finalize-failure branch destroys the only link between the take and its audio.** §5.1 line 330: `else { take.audio = {}; … INCOMPLETE asset for later repair }`. After that, the take carries no `id`, and `CaptureFacts` (firstSample, gaps, unreliableFrom) exist only in the dead `AudioTap`. A later repair produces a complete asset that no take references, and the take that was actually performed against it has permanently lost its audio. Fix: always write the reference — `segments[0] = {id, fingerprint: "", firstSample: tap.firstSample(), frames: tap.framesWritten(), rate, channels}` plus gaps/unreliableFrom in take domain — and define `resolve()` for an empty `seg.fingerprint`: no sidecar → `Incomplete` (already step 4); sidecar present → verify frames/rate/channels only and return a distinct status (e.g. `ResolvedUnverified`, reason "fingerprint never recorded; verified by length only"). Also define step (1) for `segments.empty() && !mode.empty()` — today it would deref a missing segment.

**3. BLOCKING — Lane A's commit (1) breaks the tree for every concurrent lane.** §10 Lane A: "(1) CMake + fixtures + Take changes as ONE commit … (2) AudioStore; (3) tests". §4.3's CMake edit adds `src/recording/AudioStore.cpp` to the app target and to `test_audio_tap_sync`, and a `test_audio_store` target sourcing `test_audio_store.cpp` — neither file exists until steps (2)/(3). CMake configure fails on a missing source, which kills Lane E's and every fixes-plan lane's build (they configure the same tree in their own `-B` dirs). Fix: order it Take+fixtures (no CMake) → AudioStore.{h,cpp}+CMake+tests as one commit. The stated goal "so Lane B can build the moment it lands" cannot hold either way — Lane B needs `AudioStore` to exist.

**4. BLOCKING (dispatch scheduling) — `tests/CMakeLists.txt` is owned by two lanes and neither document says so.** Audio-store Lane A owns it (§10, `:274-288` region for `test_take`-style link lists, `:325-358` for `test_audio_tap_sync`, plus a new target); the fixes plan's L0 owns it too (appends four stub TUs to `add_executable(test_take …)` at `:274-288`, optionally adds `test_record_panel`). The fixes plan flags `Take.*` and `Player.*` conflicts (its Risk 1) but not this one; the audio-store spec flags neither. Two unfenced builders in one file is exactly the s168 rig-fact class. Fix: run L0 first (20 min) then Lane A, or fold L0's four-line edit into Lane A's CMake commit. Cross-reference the `Take.*`/`LoadStats` (L1) and `Player.*` (L4) merges from the audio-store side too — it is silent on the sibling plan.

**5. NON-BLOCKING — Gap markers can be lost before they reach the sidecar.** `gapFifo_{64}` drops markers when full (`AudioTap.cpp:386-388`) and, unlike overruns, a silence-filled gap is counted nowhere else. §5.1 drains `popGap` at stop; a 4-hour set with >64 dropouts silently loses gap positions from `audio.json`. Fix: state that step 3 drains `popGap` on every 120 Hz tick into the accumulating `CaptureFacts.gapsInTakeClock`; Lane B's gap test should drain the same way.

**6. NON-BLOCKING — "`unreliableFrom` says why" is not true for one stop path.** `stopInternal()` `:448-454` gives up on still-pending frames without touching `unreliableFrom` (only the overrun branch `:347-354` sets it); only the silence-debt give-up `:461-468` is covered. The spec's Lane B invariant text (§5.1, "the only way they differ, and then `unreliableFrom` says why") is wrong for `:453`. Fix: add `framesWritten` to `CaptureFacts`; in `finalize()`, if the header's `lengthInSamples < facts.framesWritten` and `unreliableFrom` is unset, set it to `firstSample + lengthInSamples` and say so in the sidecar.

**7. NON-BLOCKING — A mid-take rate/channel change ends the audio silently, and `resolve()` cannot see it.** `AudioTap::prepare` stops the tap itself on such a change (`AudioTap.cpp:54-65`) and nothing restarts it; `tap.stop()` at show end is a no-op, `finalize` succeeds, `asset->frames == framesWritten()` holds, one segment → `Resolved`. Stamps past `firstSample + frames` then point at no audio with no signal. The spec's "multi-segment … refused loudly at resolve time" only covers `size() > 1`. Fix: in §5.1, read `tap.isRunning()` before `stop()`; if false, set `unreliableFromInTakeClock = firstSample + framesWritten` (and name the case in `Resolution.reason` when stamps exceed the asset — or leave that to step 3, but say which).

**8. NON-BLOCKING — §5.2/R3 has an unnamed 44.1-vs-48 trap.** The overdub clock must be fed asset frames, but the obvious source, `AudioTransportSource::getNextReadPosition()`, returns **device-rate** samples (`juce_AudioTransportSource.cpp:189-197`: source position × `sampleRate/sourceSampleRate`), and takes a `ScopedLock` (message thread only). With a 44.1 kHz asset on a 48 kHz device, `firstSample = 0` is off by 8.8 %. Fix: pin the domain in §5.2: `assetFrame = getNextReadPosition() × asset.rate / deviceRate` (or read the positionable source directly), and forbid calling it from the audio thread.

**9. NON-BLOCKING — The GC verdict is only valid relative to the scanned root, and nothing says so.** `unreferencedAssetIds(takesRoot)` scans one root; a take saved anywhere else (a tour SSD, the Desktop) makes its asset look unreferenced. Harmless now (query only), but §7.3's proposed "Clean up unused audio…" UI would list it as deletable — a data-loss path in waiting. Fix: `ReferenceScan` carries the roots scanned; the reason text reads "not referenced by any take under <roots>"; note multi-root or a per-asset back-reference file as the LATER option.

**10. NON-BLOCKING — The asset currently being recorded reads as `Incomplete`.** `isIncomplete(id)` / `listIncompleteAssetIds()` are true for the live recording (wav exists, no sidecar); a "Repair" run mid-show fingerprints a file being written. Fix: `AudioStore` keeps `activeAssetId_` from `beginAsset()` to `finalize()` and excludes it from the incomplete list (or documents that the caller must).

**11. NON-BLOCKING — Two stated rationales are factually wrong (conclusions survive).** (a) §4.1 `beginAsset()` comment: "a nonexistent parent reads as 0 bytes free" — VERIFIED false: `juce_doStatFS` walks up to five ancestors until one exists (`juce_SharedCode_posix.h:197-208`), and `AudioTap::start` creates the parent itself (`AudioTap.cpp:112-113`; `File::createDirectory` is recursive, `juce_File.cpp:531-545`). Creating the folder first is still fine — just fix the reason. (b) "random 128-bit id": `juce::Uuid()` draws from a fresh `juce::Random` (`juce_Uuid.cpp:38-48`), a 48-bit LCG (`juce_Random.cpp:88`) seeded from time/ticks/`this` (`:67-77`) — ≤ 48 bits of effective entropy. Adequate at this scale; say so, and have `beginAsset()` re-mint if the folder already exists. (c) §5.1 "delete the empty asset folder" — `start()` can leave a 0-byte `audio.wav` when `createWriterFor` fails after the stream opened (`:115-121`); specify `deleteRecursively`.

**12. NON-BLOCKING — Two acceptance criteria are under-specified.** (a) `[store] fp1 is deterministic and specified`: if the test writes the WAV via the float path, the "by hand" expectation depends on JUCE's float→int16 rounding, not just the `>> 16` read assumption. Specify writing through `AudioFormatWriter::write(const int**)` with `v << 16` so the stored bytes are exact by construction; also state fp1 is defined only for tap-written 16-bit PCM (the int read of a float WAV is reinterpreted bits). (b) Lane B "ThreadSanitizer run … prove it": the recipe is not named — it exists (`cmake/Sanitizers.cmake:22`, `-DADNA_SANITIZE=thread`, `.harmony/.reports/s168-fix-blocking.md:50`); cite it. Also absolute ctest counts ("306 + new") will be wrong if any fixes-plan lane lands first; state relative counts, absolute only at the final gate.

**13. NON-BLOCKING (out of scope, must be named) — A crash mid-show loses the entire take, not just the audio facts.** `PerformanceRecorder::start` stores the folder and never writes (`PerformanceRecorder.cpp:12-22`); `Take::save` runs only at §5.1's end. Ruling 24 says the log is the product; §5.1 is "the CONTRACT step 3 wires". Fix: require step 3 to write a provisional `take.json` at arm time carrying the asset id, and checkpoint `Take::save` periodically (`replaceWithText` is already atomic, `juce_File.cpp:798-802`). Combined with finding 2 this is what makes "repair later" real.

**14. NON-BLOCKING — Store location and the R15 floor, for Boris Q2.** `~/Documents` on macOS may be iCloud "Desktop & Documents" with Optimize Storage, which can evict a 2.8 GB `audio.wav` to a stub — indistinguishable from deletion at resolve time. And `kMinFreeBytes = 2 GB` (`AudioTap.h:132`) is below one 4-hour night (2.76 GB); the tap will arm on a 2.5 GB-free disk and hit the overrun path at hour ~3.6. Fold both into Q2; the floor change is `AudioTap.h` (see finding 1's ownership fix).

**15. NON-BLOCKING — Doc nits.** `mode` copied by `referencing()` describes how the *audio* was captured, not the re-do session — say so in §2.1/§5.2. `AudioAsset::recordedAt` "ISO-8601 UTC": `Time::toISO8601` emits a local offset unless the builder converts. `listAssetIds()` "complete only" should define complete = sidecar parses and `id == folder stem`.

**Checked and sound (so nobody re-derives them):** `assetFrame = sample − firstSample` matches `AudioTap.cpp:178` and T1's `w + firstSample == exactSample` proof (`test_audio_tap_sync.cpp:274`); gap/unreliableFrom domain round-trip is integer-exact; the periodic-anchor error bound (0.03/60 × 15 s ≈ 0.0075 beats vs the 0.05 test bound) and the pre-change failures (1.2 beats; `sampleAt` returning the start sample per `TempoMap.cpp:90-104`) are correct; `bracketByBeat` stays unambiguous with periodic anchors; I hand-traced all three `[player][seek]` cases against the specified `seek()` semantics and `Player.cpp:12-89` — every expected count matches; no lane touches the audio thread (AudioStore, RecorderClock, Player are all message-thread; the only RT-adjacent addition, the flush in finding 1, runs on the `TimeSliceThread`); v1/v2 fixtures still load under `kFormatVersion = 3` (`Take.cpp:189-200`); R5's between-lanes window holds because `file` still round-trips.

**VERDICT: NEEDS REVISION — 4 blocking (1: no WAV header flush, so the crash-repair story is void; 2: finalize-failure blanks the take's audio reference; 3: commit (1) references nonexistent files and breaks every concurrent build; 4: unflagged `tests/CMakeLists.txt` ownership overlap with the fixes plan's L0). All four are small spec edits — finding 1 needs one line in `AudioTap.cpp` and an ownership change; none changes the design (store, id, fp1, v3, refuse-loudly, query-only GC, periodic anchor, seek semantics all hold). Eleven non-blocking items, of which 5-8 (gap drain, the `:453` give-up, self-stopped tap, overdub clock domain) should be folded into the spec text before Lane B and step 3 are dispatched.**
