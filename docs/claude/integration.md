### Output & Integration System (P22)

**Production REST API** (`ApiServer`, port 7070, always-on): 41 registered routes total (all functional; `/api/set_bpm` wired Wave 0 — drives the TopBar manual-BPM override path via the message thread; `/api/resync` added s-rta-0925 — manual Resync via `BPMTracker::requestResync()`, message thread → analysis thread, same funnel as the TopBar Resync button). cpp-httplib on a background thread with CORS headers. 27 core control endpoints: /api/health, /api/status, /api/composition (the show: see below), /api/trigger_clip, /api/trigger_column, /api/set_param, /api/set_layer_opacity, /api/set_master_signal, /api/switch_deck, /api/snapshot, /api/bpm, /api/set_bpm, /api/resync, /api/features, /api/inject_features (test-mode only — 404 in production), /api/load_image, /api/load_source, /api/load_composition (answers after the staged swap completes -- s-rta-0929 asyncload; see rendering.md 'Asynchronous loads'), /api/set_effect, /api/effects, /api/sources, /api/render_frame, /api/reset, /api/set_effect_chain, /api/state, /api/syphon, /api/set_syphon. Plus 7 `/api/perf/*` performance-recorder endpoints and `POST /api/audio/source` (both documented in "Audio Store (Ruling 28)" in `docs/claude/recording.md`), plus 6 `/api/routine/*` endpoints (`save`/`fire`/`stop`/`set`/`remove`/`status` — s-rta-0926 routines slice 1, documented in "Routines" in `docs/claude/recording.md`). All GL mutations go through existing thread-safe APIs.

**The show over REST (lane bf9b, s-rta-1002b; plan-bf9b F8)**: `GET /api/composition` carries the TRUTH as a top-level `layers` array -- the shared stack, each layer's settings (`index`, `id`, `name`, `type`, `opacity`, `visible`, `muted`, `solo`, `bypassed`, `ignoreColumnTrigger`, `blendMode`, the `live` block) and what it plays: `activeClip` / `previousClip` / `pendingClip` = `{deck, deckId, column, clipId, retired}` (`deck` -1 and `retired` true for a removed deck still playing; `column` -1 = none) and `crossfadeProgress` -- plus `retiredDeckCount`. `decks[d].layers[l]` stays as a legacy MIRROR (probe readers): the shared layer's settings, `activeClipColumn` / `previousClipColumn` as seen from deck d (-1 when the ref names another deck), `crossfadeProgress`, and deck d's row-l clips. REST never reads a retired deck's cells. `/api/trigger_clip`, `/api/trigger_column` and OSC `/audiodna/clip/{layer}/{column}` fire the SHOWN deck's cells into their rows' shared layers (a column fire skips Ignore Column layers and empties a layer whose cell is empty); `/api/switch_deck` and OSC `/audiodna/deck/{n}` change only the grid; `/api/set_layer_opacity` and the OSC layer routes address the shared layer. There is no REST / OSC deck-fade field, and there never was: `Composition::globalTransitionSpeed` (deleted) was written only by the TopBar "Fade:" slider. TEST-ONLY (test-server builds, the `/api/debug/load_deck` pattern): `POST /api/debug/remove_deck {"deck": i}` = the deck tab menu's Remove Deck, `POST /api/debug/undo` = the app's Undo (Cmd+Z); `GET /api/debug/ui_text` also answers `load_notice` (the header's yellow load notice: an old show converted, a routine load note, the deck-id refusal). Live: `.harmony/probe-boxes.sh`.

**OSC Input** (`OscHandler`, `juce_osc` module): Receives OSC on configurable UDP port. Address patterns (14): `/audiodna/clip/{layer}/{column}`, `/audiodna/layer/{n}/opacity|bypass|solo|mute`, `/audiodna/deck/{n}`, `/audiodna/master`, `/audiodna/signal`, `/audiodna/bpm`, `/audiodna/resync`, `/audiodna/snapshot`, `/audiodna/effect/{name}/{param}`, `/audiodna/macro/{n}`, `/audiodna/routine/{slot}`. Uses `MessageLoopCallback` template parameter for thread-safe dispatch on JUCE message thread. **LIVE 2026-07-17 (Wave 1-B)**: `OscHandler::startListening(8000)` is called unconditionally at startup (like ApiServer), so the receiver binds UDP port 8000, and all 14/14 pattern callbacks are wired in MainComponent (`/audiodna/signal` added s-rta-0925 mastersignal Step 1; `/audiodna/resync` added s-rta-0925 resync; `/audiodna/routine/{slot}` added s-rta-0926 routines slice 1 — value > 0 fires the routine pad, 0 ignored) — each routing through the same handler as the equivalent REST/UI/MIDI path. Port is hardcoded (no preferences UI configures it yet).

**MIDI Output** (`MidiOutputHandler`): Sends note-on/off to hardware controllers (Launchpad X/Mini MK3) for clip state feedback. 5 states: Empty(off), Loaded(velocity 5), Playing(velocity 60), Triggered(velocity 52), ActiveWithFx(velocity 62). Polls deck state ~6Hz from timerCallback. Note mapping: `(layer+1)*10 + (column+1)` for Launchpad grid layout.

**Video Recording** (`VideoRecorder`): Real-time capture from GL framebuffer to H.264/ProRes/MJPEG via FFmpeg. Triple-buffered pixel readback (GL thread does `glReadPixels` into rotating CPU buffers, encoder thread picks up via condition variable). No mutex on GL thread hot path. Codec selection via `VideoRecorder::Config`. Menu: Output > Start/Stop Recording. Saves to ~/Documents/Audio-DNA/Recordings/.

**Snapshot** (`Renderer::takeSnapshot()`): Saves timestamped PNG to ~/Documents/Audio-DNA/Snapshots/. Uses existing `captureFrame()` infrastructure. Bindable via `Binding::Action::Snapshot`. Also available via REST API (`POST /api/snapshot`).

**Syphon Output** (`SyphonOutput`, macOS only, optional): Zero-copy GPU texture sharing via IOSurface. Obj-C++ wrapper around `SyphonServer`. Uses `__has_include(<Syphon/Syphon.h>)` for compile-time detection. Enable with `-DAUDIODNA_BUILD_SYPHON=ON` + install Syphon.framework to /Library/Frameworks/. **WIRED 2026-07-17 (Wave 1-A)**: `init()` runs on GL-context creation and the final composited frame is blit→published once per frame, gated on enabled + initialized; Output → "Syphon Output" menu toggle controls it (default OFF each boot, no persistence). Build-flag-gated — a runtime no-op unless built `-DAUDIODNA_BUILD_SYPHON=ON` with Syphon.framework installed. Post-publish, `publishSyphonFrame` re-binds `defaultFBO` so the subsequent `glReadPixels` capture path is unaffected.

**Output windows (s-rta-0927 outputs-c1/c2/c3, Pitfall 40)**: the composition on any number of connected displays, the main screen included -- one borderless window per display. It shows the COMPOSITION -- the main Renderer's canvas, shared through IOSurface frames (`src/output/SharedFrameSet.h`, `OutputPresenter.h`) -- letterboxed to the composition's shape, at normal window level, and it can never take the keyboard (`windowIgnoresKeyPresses`). It no longer renders its own effect chain or the legacy image. macOS only (IOSurface; elsewhere the window stays black).
- Two doors, ONE item list (plan5 C2): the Output menu shows one tickable item per connected display -- "Display N (WxH)", "Display 1 (WxH, main)" -- (click = toggle that display's output; tick = live), then "All Outputs Off"; the TopBar "Outputs: Off" / "Outputs: N" button opens the SAME list. Both come from `output::buildOutputMenu` (`src/output/OutputMenuModel.h`) through `OutputManager::populateMenu` (`src/output/OutputManager.h`, message thread). The live windows are the only truth: the old hidden MainComponent combo and the TopBar combo are gone. A closed window is hidden at once and destroyed on the next message-loop turn.
- Keys (`output::classifyOutputKey`, `MainComponent::keyPressed`): Cmd+Shift+Esc closes every output (tested BEFORE the bare-Escape case -- `KeyPress::isKeyCode` compares the key code only); Cmd+` brings the app window back above an output that covers it; Cmd+F toggles the output on the main display; plain Esc no longer touches outputs (still swallowed; plan5 Q2). Cmd+F and Cmd+` need Shift UP (Cmd+Shift+F / Cmd+Shift+` are not output keys; outputs-c3). The output window has no key handling: the app keeps the keyboard even while covered.
- Outputs are machine state, never file state: no deck or composition opens one (a deck file's `outputDisplay` is written 1 and ignored on load, plan5 R7; `Composition::outputDisplay` has no reader).
- Hot-plug (plan5 C3, `OutputManager::reconcile`, one idempotent message-thread function over `output::diffOutputs`, `src/output/OutputTargets.h`): a live output whose display is unplugged closes (its target is kept as INTERRUPTED) and reopens by itself when that display comes back (plan5 Q6); a display that moves in the arrangement, changes mode (resolution / scale) or becomes / stops being main keeps its output (the window follows, `setBounds`); an output never jumps onto a display that did not change, and an interrupted target never reopens on one. Triggers: every live window's `parentSizeChanged()` (JUCE calls it on every peer after `Displays::refresh()`) schedules the reconcile for the next message-loop turn (never inside the window's own callback), and `OutputManager::pollDisplays()` runs on EVERY 30 Hz UI timer tick (a cached comparison; it reconciles only when the display list differs from the last one seen -- also when no output is live). The menu ticks, the TopBar count and `/api/state.outputs(.displays)` are rebuilt on every reconcile. All Outputs Off / Cmd+Shift+Esc also cancels every pending reopen.
- Saved set (plan5 C3): the WANTED outputs (live + interrupted + the saved targets not yet restored, `output::wantedSet`) are saved in settings.json `"outputs": {"version": 1, "targets": [{x, y, w, h, scale, main}]}` on a change only (never per tick): a manual close removes a target, a hot-plug close keeps it, quitting writes nothing (quit with the outputs on to keep them). A saved target Restore has not opened stays in the file (a partial Restore, another output change, All Outputs Off) until it is restored or its display is opened/closed by hand -- the key is replaced whole on each write, so leaving it out would lose it. The app NEVER opens an output by itself at launch or on a composition/deck load (plan5 Q1): the set is only loaded, and Output > "Restore Last Outputs" (right below All Outputs Off in both doors; `kOutputRestoreLast` 1697, appended) opens its targets whose display is connected and free -- greyed out when there is nothing to open.
- settings.json (`~/Library/Audio-DNA/settings.json` on macOS -- JUCE's `userApplicationDataDirectory` is `~/Library` there) is ONE object with independent keys (`milkDropPresetDir`, `outputs`), read and written only through `AppSettings` (`src/model/AppSettings.h`: read-modify-write, unknown keys kept, a corrupt file rewritten valid), so neither writer clobbers the other. Test-server builds in `--test-mode` honour `AUDIODNA_SETTINGS_FILE` (an absolute path) instead, and without it use a scratch file (`AppSettings::testModeFile`: `~/Library/Caches/Audio-DNA/test-mode-settings.json`, one per run; err.log `[Settings] test mode: ... scratch settings <path>`), so a test-mode app never touches the real file.
- `/api/state` (7070 and 8080) reports `outputs` {live, tap, frame_gen, frame_serial, canvas_w, canvas_h, displays: [{index, x, y, w, h, scale, main, live, label}]} (`displays` = the Output menu's list, `label` its exact title; `OutputManager::stateVar`, rebuilt on the message thread after every change and every reconcile). Screen-safe live witness: `.harmony/probe-outputs.sh` (test mode, offscreen, never a window; each run on a scratch settings file).
- `/api/state` (7070 and 8080) reports the render thread's trigger-tuple witnesses (lane tsan, s-rta-1002; Pitfall 63), monotonic counts since launch, relaxed `uint64` counters owned by the Renderer: `render_pending_fired` (queued beat-snap triggers the GL thread fired: `processPendingTrigger` transitions that changed the tuple), `render_autopilot_advances` (autopilot advances that changed the tuple) and `render_tuple_adopts` (fade ticks whose single CAS lost to a concurrent trigger and adopted its tuple -- INFO only, expected ~0). `.harmony/probe-tsan.sh` scenario d requires the first two >= 1 per lane launch (the render writers ran).

**Syphon Input / Spout / NDI**: REMOVED 2026-07-17 (Wave 0) — `SyphonInput` (.mm/.h, orphaned), `SpoutOutput.h` (Windows header-only no-op), `NdiOutput.h`/`NdiInput.h` (stubs) were all deleted.

### Smart Audio Features (P23)

**Genre Detection** (`GenreDetector`): Real-time 8-genre classification from audio features. Uses multi-feature scoring (BPM range, spectral profile, transient density, chromatic complexity) with ~2s EMA smoothing and ~3s hysteresis. Runs as stage 13 in the AnalysisThread pipeline. Zero allocation in steady state. Genres: House (0), Techno (1), DnB (2), Hip-Hop (3), Ambient (4), Rock (5), Pop/Electronic (6), Jazz/Other (7). Also tracks energy state (0=low, 1=medium, 2=high).

**Auto-Preset Selection**: When `composition.autoPresetOnGenre` is enabled, genre changes fire `Renderer::onGenreChanged_` callback on the message thread. The genre deck auto-switch (`composition.genreDeckAssignment[8]`, genre→deck index) is INERT since lane bf9b: a deck switch no longer changes the picture, so it would only move the grid; the assignments stay in the file and one logLine per session says so (`docs/claude/effects.md`).

**AI Mapping Suggestions** — REMOVED 2026-07-17 (Wave 0): `MappingSuggester` (.cpp/.h) was a ghost (never instantiated, no UI or API caller) and has been deleted.

**Smart Random Autopilot**: When `smartRandomEnabled` is active and autopilot action is PlayRandom, clips are selected based on structural state and energy level instead of pure random. Convention: lower column indices = calmer content, higher = more intense. Drop→intense clips, breakdown→calm clips.

**Structural Scene Triggering**: `Renderer::onStructuralStateChanged_` fires on structural transitions (normal/buildup/drop/breakdown). Controlled by `composition.structuralSceneEnabled`.

**ISF Shader Import** (`ISFShaderLoader`): Imports Interactive Shader Format (.isf/.fs) shaders from isf.video. Parses JSON metadata from comment blocks, extracts parameter definitions (float/bool/long), wraps GLSL with ISF compatibility defines (`TIME`, `RENDERSIZE`, `isf_FragNormCoord`, `IMG_NORM_PIXEL`), converts to GLSL 410. Registers as effects in EffectLibrary with "ISF" category. Menu: Audio-DNA > Import ISF Shader... **PHANTOM**: parse/convert/register work and the effect appears in the FX browser, but `MainComponent::handleImportISF()` never compiles or queues the converted GLSL for the GL thread (the compile step is a TODO no-op) — so imported ISF effects render nothing. The "Import Successful" dialog is misleading.

**Per-Genre Smoothing** — REMOVED 2026-07-17 (Wave 0): `GenreSmoothing.h` was dead code (never instantiated, not wired into MappingEngine, self-refs only) and has been deleted; its One-Euro filter variant was also removed from `Smoother.h`.

**Smart BPM Recovery**: `BPMTracker::feedSilenceDetection(rms)` detects silence (RMS < 0.005 for 300ms) and holds the last good BPM. Phase continues free-running during silence. Resumes after 100ms of audio above threshold. Prevents BPM jumping to 0 during DJ transitions or track endings.

### Advanced Audio Analysis (P25)

**AdvancedAudioAnalyzer** (`src/analysis/AdvancedAudioAnalyzer.h/cpp`): Computes 5 advanced spectral features per hop, added as stage 14 in the analysis pipeline. All buffers pre-allocated, zero allocation in steady state.

| Feature | Algorithm | Output | Uniform | Use Case |
|---------|-----------|--------|---------|----------|
| **Sidechain Pump** | Pearson correlation of bass vs mid envelopes (64-hop window). Negative r = pumping. | [0, 1] | `u_sidechainPump` | Techno/house sidechain detection |
| **Swing Ratio** | Inter-onset interval histogram. Consecutive pairs long/short ratio. | [0.5, ~0.67] | `u_swingRatio` | Hip-hop shuffle detection |
| **Formant Presence** | Energy ratio in 300-3000 Hz vocal range vs total. Adaptive normalization. | [0, 1] | `u_formantPresence` | Vocal content detection |
| **Resonance Peak** | Spectral kurtosis in 200-8000 Hz. High = sharp filter peaks. | [0, 1] | `u_resonancePeak` | Filter sweep/synth resonance |
| **Reese Bass** | Spectral spread (weighted std dev) in 30-200 Hz. Wide = detuned/wobble. | [0, 1] | `u_reeseBass` | DnB reese bass detection |

All 5 features are available as MappingSource enum values (`SidechainPump`, `SwingRatio`, `FormantPresence`, `ResonancePeak`, `ReeseBass`), as hidden signals in SignalRegistry, and as shader uniforms in all 3 render paths.
